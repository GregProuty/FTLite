# Codex review: 2b-ii spec (HUD and test plan half, 2026-11-10)

1. **P1 — Inconsistent Weapons timings.** [Spec line 108](/C:/Users/djuar/FTLite/docs/superpowers/specs/2026-11-10-scanning-and-torpedoes-design.md:108) combines a 12 s charge with a 13.3 s load. Existing `weapons.test.ts` establishes starter Weapons output as **0.5**: charge takes `6 / 0.5 = 12 s`, loading takes `10 / 0.5 = 20 s`. **Fix:** use 12 s / 20 s for starter Weapons, or explicitly configure level 3, output 0.75, and use 8 s / 13.33 s.

2. **P2 — Manual gate asserts incorrect stock counts.** [Spec line 119](/C:/Users/djuar/FTLite/docs/superpowers/specs/2026-11-10-scanning-and-torpedoes-design.md:119) expects switching to Torpedo to start loading with stock 3, although §5 loads whenever Weapons is occupied, regardless of selector. After firing, remaining seated automatically loads another torpedo and consumes another stock unit; stock need not return to 3 after one regeneration. **Fix:** observe loading from the initial Weapons sit, expect stock 2 upon completion, fire, then stand immediately to prevent reloading. Measure regeneration from its existing progress, or reset progress explicitly in an automated fixture.

3. **P2 — Starting-state requirements lack assertions.** [Spec line 109](/C:/Users/djuar/FTLite/docs/superpowers/specs/2026-11-10-scanning-and-torpedoes-design.md:109) covers serialization and hashing, but neither proves §3’s initial values or unchanged `layoutHash`. The existing fresh-state debris test checks only old fields. **Fix:** assert selector 0, stock `TORP_START`, all other new fields zero, and the existing layout hash.

4. **P2 — Scan no-op cases omit an already-running scan.** [Spec line 104](/C:/Users/djuar/FTLite/docs/superpowers/specs/2026-11-10-scanning-and-torpedoes-design.md:104) can test Confirm on scanned/empty targets only from `scanning = 0`, missing §4’s “Confirm never stops a scan” and scanned-target pause behavior. **Fix:** start scanning, repeat Confirm, then select a scanned target and Confirm again; assert `scanning` remains 1 and neither object’s progress changes while the scanned target is selected.

5. **P2 — Revealed information surviving a stand is untested.** [Spec line 104](/C:/Users/djuar/FTLite/docs/superpowers/specs/2026-11-10-scanning-and-torpedoes-design.md:104) tests standing during an unfinished scan, but omits §4’s permanent `scanned` and frequency state after completion. **Fix:** complete a scan, stand and fail Science, and verify `scanned`, frequency, and the HUD frequency suffix remain intact.

6. **P2 — Selector changes preserving charge lack coverage.** [Spec line 105](/C:/Users/djuar/FTLite/docs/superpowers/specs/2026-11-10-scanning-and-torpedoes-design.md:105) checks selector cycling and persistence, but omits §5’s requirement that selection leave beam charge unaffected. **Fix:** cycle through all selectors with partial and full charge, asserting preservation; account for ordinary charging if testing through `step()`.

7. **P2 — Invalid-target torpedo attempts lack consumption assertions.** [Spec line 106](/C:/Users/djuar/FTLite/docs/superpowers/specs/2026-11-10-scanning-and-torpedoes-design.md:106) covers an unloaded tube, but omits §5’s loaded torpedo with no valid target. Existing no-target coverage exercises only the beam. **Fix:** test cursor −1, inactive target, and unwarned target with `loaded = 1`; assert unchanged loaded state, stock, and combat RNG.

8. **P2 — Shot-count property can pass without exercising shots.** [Spec line 107](/C:/Users/djuar/FTLite/docs/superpowers/specs/2026-11-10-scanning-and-torpedoes-design.md:107) requires random scripts but no minimum duration or successful firing opportunities. Zero shots and zero draws satisfy the equality; stock-decrease assertions likewise pass without a load completion. **Fix:** require generated scenarios to reach load completion and ready, valid-target Confirms, and derive expected shots from pre-action readiness rather than observed firing results.

9. **P2 — Global HUD torpedo fields lack live-state coverage.** [Spec line 110](/C:/Users/djuar/FTLite/docs/superpowers/specs/2026-11-10-scanning-and-torpedoes-design.md:110) names the Weapons panel’s torpedo block but omits §8’s separate `HudModel.weapons.torpedoLoaded` and `torpedoStock`. Null-state assertions cannot verify their live mapping. **Fix:** assert both global fields with loaded/unloaded states and distinct stock values, including while nobody occupies Weapons.
