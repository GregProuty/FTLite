# Codex review: Run-ii spec half 1 (2026-11-11)

1. **High — §6, “Arrival” and “The list” (lines 1–2 of those subsections).** The new arrival step adds scrap and draws an event, but does not say how `jumpShip` obtains the destination when the Navigation console is absent or its cursor is invalid. Run-i’s `jumpShip` reads the cursor, clamps it to `reachable`, and defaults to the first destination when there is no Navigation station; the proposed explicit argument removes that fallback. **Fix:** specify a default/no-op policy for missing or invalid destinations, and update every direct caller and jump test to pass a valid destination or exercise that policy.

2. **Medium — §6, “Cursor”.** Re-clamping after a buy is internally unclear: it says to clamp to the first selectable row, then says the cursor stays on the item after a buy. These differ when a purchase disables or relabels that item as owned. **Fix:** say to preserve the cursor if its row remains selectable, otherwise move it to the first selectable row.

3. **Medium — §8, “The upgrade’s effect”.** The spec says every caller of `maxLevel` updates, but does not say that `isOverdriven`’s current second argument is a **station index**, while `maxLevel` takes a **station kind**. It also asks for `baseMax(state, kind)` while existing `stationOutput` deliberately divides by `STATION_MAX[kind]`; callers could incorrectly change that denominator and erase the stated output increase. **Fix:** define parameter semantics explicitly, enumerate affected callers, and state that only the overdrive threshold and displayed maximum use `baseMax`; keep the output denominator at `STATION_MAX`.

4. **Medium — §7, event 4, “Strip it bare”.** “A station fails” does not constrain the random selection to a working station, while the parenthetical explicitly allows selecting an already-failed station and skipping the call. The former can read as “always fail a station”; the latter means the choice can have no failure effect. **Fix:** state whether the draw selects among all stations or only operational ones, and whether the effect is allowed to select an already-failed station.

5. **Low — §7, event 5, “Treat the crew”.** The spec names `Health.cur` and `Life` but does not identify the enum value for Conscious, nor specify whether healing a Conscious member includes one at zero health before the crew lifecycle updates their state. **Fix:** define eligibility as `Life.state[eid] === LifeState.Conscious` at effect time and state that Downed members are untouched.

The flatten counts and manifest placement described in §4 match the current Run-i layout arithmetically: adding `nodeType`, three scalar fields, and `STATION_COUNT` upgrades yields the stated `RUN_FIELDS`; four new telemetry scalars take the count from 16 to 20. The proposed map draw placement also preserves Run-i’s edge draws, and `loot` is the fourth named stream. The named fire, breach, station failure, and crew helpers support the specified effects as written.
