# Codex review: Combat-ii spec half 2 (2026-11-11)

1. **High — §9 line 117; §10 line 124:** Identical survival figures are unjustified. Arrival’s extra `rng.hazards` draw shifts subsequent shot rooms, flight times, frequencies and impact effects; resulting crew activity can also change director behavior. **Fix:** retain the existing survival assertions, rerun seeds 1–3, and record new figures. Remove “if they differ, a rule leaked”; define a fallback if survival fails.

2. **Medium — §7 lines 86–89:** The shared HUD contract is incomplete. `DebrisTarget` does not declare `shieldsUp`; required `system`/`status` additions also affect object literals and exact fixtures. `repairIn` has no units. **Fix:** declare every field and variant explicitly: objects/hull have `system/status = null`; subsystems have system index and raw HP; define `repairIn` as seconds using `ceil((repairTick-tick)/TICK_HZ)`; declare `shieldsUp` with defined values for every target kind.

3. **Medium — §7 line 86; §9 line 114:** Science suffix rounding is unspecified. Existing `targetRowText(t, scan)` uses `floor`, whereas hull/system percentages use `round`. **Fix:** prescribe the complete format, e.g. `Enemy 64% 87s S? 40%`, using `floor(scan*100)`; test fractional progress, scanned suppression, and unscanned shields-down output `Enemy 64% 87s S- 40%`. Explicitly prioritize `S-` over revealed frequency.

4. **Medium — §8 line 101:** “Two beams (24 s)” implies guaranteed disables despite the stated 70% hit rate. Charging two shots takes 24 s at output 0.5; obtaining two hits can take longer. **Fix:** say “two successful beam hits”; label 24 s as the all-hit charging minimum. Seven **hits**, rather than seven attempts, destroy 100 hull.

5. **Medium — §9 lines 105, 109:** The threshold migration omits the existing `enemyBeamHits` assertions and leaves clamping inconsistent with §5’s unclamped formula. **Fix:** replace the old import/calls with state-aware checks. With engines up, preserve all four results: `0.69/0.71` at output `0.5` → `true/false`; `0.84/0.86` at output `1` → `true/false`. Add engines-down `0.84/0.86` → `true/false` at output `0.5`. Define whether thresholds clamp above output 1, then test that policy.

6. **Medium — §9 lines 105, 109:** Existing Combat-i assertions conflict with shielding. In `tests/enemy.test.ts:201`, F3 against the helper’s default shield frequency 1 must now return `false`, leaving hull `100`, with `shots/hits = 1/0` and combat RNG unchanged. **Fix:** state that replacement explicitly, or change that fixture to shield frequency 3 and retain its hit expectation. Preserve matched F1 and torpedo assertions.

7. **Medium — §9 lines 108, 114:** “Existing fixtures updated” omits concrete target/HUD changes. **Fix:** specify `[a,8,b] → [a,8,9,10,11,b]`; Down traversal becomes `8→9→10→11→b→a`. In `hud.test.ts`, both nine-target model lengths become `12`; with cursor still on hull index 8, existing first indices remain Weapons `3`, Science `2`. Add last-subsystem cursor index `11`, yielding first indices `6/5`. Existing hull text expectations become `Enemy 64% 87s S?` and, for Science progress 0.4, `Enemy 64% 87s S? 40%`.

8. **Medium — §9 lines 107, 110–112:** Several bullets lack reproducible fixture setup. Repeated successful beams require recharging **and resetting the combat state before each shot**; otherwise seed 7 only pins the first roll. The helper also omits reset rules for repair timers and scan state. **Fix:** define those resets and fixture ticks explicitly. Pin arrival hazards state 7 to frequency `1` and final RNG state `1831565820`; use combat state 7 per hit and 4 per rolled miss. Change line 111’s threshold “drops to 0.85” to “rises to 0.85” at output 0.5.

9. **Medium — §9 lines 111–112:** Required §5–6 behavior lacks enemy-specific coverage: exact repair boundaries/order, no repair-timer extension on an already-down system, scan stand/offline/resume behavior, and pseudo-slot safety for slots 9–11. The existing debris read trap catches only slot 8. **Fix:** test `repairTick-1` versus `repairTick`, repair before departure/fire, unchanged timer after further damage, scan pause/resume and scanned/absent Confirm guards; extend the trap across all four enemy slots and test enemy-only productivity remains false outside an active hull scan.

10. **Medium — §9 line 113:** “Continuation through a repair and a shielded miss” can pass by hash equality without either event occurring; “shielded miss” also conflates absorption with a rolled miss. The nine enemy scalars exclude the new telemetry scalar. **Fix:** pin seed, save tick, repair tick and firing intent; assert the repair and chosen shot outcome occurred before comparing hashes. Round-trip/hash-test all nine enemy scalars **plus `enemyDisables`**. Change both existing version-rejection fixtures from `9` to `10`.

11. **Medium — §9 line 115:** Record/table fixture changes are underspecified against exact equality and anchored regex tests. **Fix:** keep record `version: 1` and header `enemy`; add `disables: 0` to default record fixtures, set `enemyDisables = 3` for the mapped example and expect `{ met: 2, destroyed: 1, disables: 3 }`. Change acceptance row regex tails `0\/0$ → 0\/0\/0$` and `2\/1$ → 2\/1\/3$`, with corresponding fixture values.

12. **Medium — §9 line 116:** The extended combat gate omits the selector transition, pinned rolls and original deadline assertions. **Fix:** retain `makeState(2,1)`, quiet director, suppressed enemy fire and original departure deadline; place shield frequency 2, fire charged F1 once, switch to F2, and reset combat state 7 before every subsequent shot. Change local shot count `7→8` and telemetry tuple `[7,7,1]→[8,7,1]`; retain absent-enemy and `tick < depart` assertions.

13. **Medium — §10 line 125:** The manual gate promises hits on matching/any frequencies, but engines still cause misses. Disabling weapons also leaves existing shots in flight, and repair replaces DOWN immediately rather than displaying `DOWN 0s`. **Fix:** require matching frequencies to permit hits, shields-down frequencies to permit rolls, no **new** enemy shots while weapons are disabled, existing shots to resolve normally, and the repair transition back to intact HP.

14. **Low — §10 lines 122–125:** The proposed gate lacks the separate evidence entries used in `docs/gates.md`, including an acceptance-table run exercising the new column. **Fix:** provide separate automated, survival, combat, acceptance and final-check checkboxes; record a dated `npm run acceptance 5 1` table with three-part enemy cells, and leave the human playtest unchecked.
