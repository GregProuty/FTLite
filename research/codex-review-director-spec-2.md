# Codex review: 4-i spec (HUD and tests, 2026-11-10)

1. **High — Spec line 124: the stall fixture triggers the stress exit first.** Three unattended fires produce raw stress `0.75`; smoothing gives `0.375, 0.5625, 0.65625, 0.703125`, reaching Peak at 20 s, before the 60 s stall. Fires can also spread or extinguish during full simulation. **Fix:** isolate `phaseStep` with stress below `0.7`, positive budget, and controlled spawn history; assert Build Up one tick before the stall boundary and Sustain Peak at it. Separately test `lastSpawnTick > phaseTick` and the initial `lastSpawnTick = -1` case.

2. **Medium — Spec line 124: the remaining transition fixtures need explicit control of competing conditions.** A directly assigned stress can change during the same tick’s recompute. “Regardless of stress” at 60 s can pass through the earlier low-stress exit if stress decays naturally. Positive-only timing checks also permit premature transitions. **Fix:** suppress recomputes or use controlled phase-helper fixtures; keep competing exits false and assert immediately before and at each boundary. For budget exhaustion, hold stress low, prevent stall, force a successful due spawn, and verify the budget decrement.

3. **High — Spec line 127: the routing test requires the wrong weights.** Section 7 awards the bonus to **one** type. With Doors idle longest, fire and breach tie, so fire wins by enum order. Both must not gain `+4`. **Fix:** at minute zero with no previous type, expect `[8, 2, 2, 4]`; add positive Engineering and debris winners, plus exactly-60-s versus greater-than-60-s cases.

4. **Medium — Spec line 125: explicit weights bypass the behavior being tested.** Passing an already reduced fire weight to `chooseType` succeeds even if `typeWeights` ignores `lastType`, or successful spawning never updates it. **Fix:** force a successful spawn, assert `lastType`, obtain the subsequent weights from `typeWeights(state)`, then test selection boundaries. Include breach/power’s minimum weight of `1` and halving before the routing bonus.

5. **Medium — Spec line 123: the stress fixtures can hide incorrect weights and omit attendance requirements.** If “one of each” means one combined state, its raw total is `1.35`, clamped to `1`; several incorrect coefficients produce the same result. Failed-station and Downed-crew attendance, Conscious-only attendance, and breach reach boundaries have no stated tests. **Fix:** test each contribution separately below saturation; add attended/unattended pairs for every applicable category, including nearby Downed/Dead crew who must not count as attendants.

6. **Medium — Spec line 128: `sinceProductive` tests omit the reset prerequisites and stamp behavior.** A counter that resets whenever `isProductive` is true could pass the stated Navigation case while incorrectly resetting an unmanned or offline station. Section 7 also explicitly requires Weapons and Life Support’s stamp predicates. **Fix:** test occupied/productive, unoccupied/productive, offline/productive and occupied/unproductive cases; cover stamp activation and expiry for both named stations.

7. **Medium — Spec line 129: snapshot equality can miss fields omitted from both serialization and hashing.** Existing snapshot tests compare hashes and reserialized snapshots; those comparisons can agree despite lost state. Only three director fields receive explicit hash-mutation coverage. Section 4’s complete initial state also lacks a stated test. **Fix:** directly compare all eight scalars and seven counters after loading distinct non-default values, independently mutate every field for hash coverage, and assert initialization. Preserve both header and flattened-version rejection checks; count the two actual continuation transitions.

8. **High — Spec lines 131 and 139: the soak can finish its loop without simulating 20 minutes.** `step()` returns immediately after game over. Existing bots repair/revive but provide no deliberate healing or debris defense. A probe using the current spawner and two recruit bots ended seeds 1–3 at approximately **363, 804 and 767 sim seconds**; this is baseline evidence, not a director result. Phase-count and range assertions could already have passed before termination. **Fix:** specify seed, crew and survival strategy; assert `tick === 72_000` and no premature ending. Measure inactivity from `max(lastSpawnTick, phaseTick)`, not total Build Up duration. Twenty sim minutes means **72,000 advancing ticks**, not twenty wall-clock minutes; benchmark the implemented director and set its test timeout explicitly.

9. **Medium — Spec line 126: the “floor at minute 20” test cannot prove clamping.** At minute 20, the unclamped formula already equals `30 / 3 = 10`; deleting `max(SPAWN_INTERVAL_MIN, …)` still passes. The referenced worked numbers also overstate the weight change: at minute 10 the unmodified doubled table is `[4, 2, 6, 8]`, making power triple its initial weight and debris double. **Fix:** add minute 30, expecting `10` rather than `7.5`, and correct the worked weight description.

10. **Medium — Spec lines 121 and 125: absorbed spawner fixtures need phase-aware adaptation.** The existing forced Navigation-failure loop repeatedly schedules attempts for 2,000 ticks but never replenishes a cycle budget or restores Build Up. Under the director, spawning can stop before Navigation is selected. Conversely, a cap test performed outside Build Up can pass merely because that phase forbids spawning. **Fix:** explicitly establish Build Up, positive budget, low stress and a due attempt in each spawn fixture; use the known power-roll fixture and restrict eligible targets for the same-tick occupant test. Assert RNG advancement and timer rearming so cap tests prove an attempt occurred.
