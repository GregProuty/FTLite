Validate these relationships and scenario-specific records, recompute/check cleanup aggregates against validated process records, and add negative mutation tests. 2. **The stale fence compares check times against a reconstructed, later deadline.** `scripts/network/online-recovery-utility.ts:41` timestamps the outgoing `lease-request` in the parent-port wrapper and `:44` sets `deadlineMs = start + 12000`. The real gate samples before nonce generation and `onRenew`, stores that earlier sample (`src/network/session/leaseGate.ts:70`), and also takes the minimum with service expiry (`:84`). Consequently, the observer permits a window between the actual deadline and its inferred deadline and does not represent an earlier service-expiry bound. A post-deadline authority check in that window would be counted as valid. The observed successful run has a margin, but the trace cannot establish that this margin exceeds the unrecorded sampling-to-IPC delay. Observe the exact gate request-start and accepted deadline through the same fail-closed passive transform, preserve decisions, and test a deliberately delayed outgoing request observation. No product lease change is implied.

3. **Cleanup can overrun the claimed 90-second absolute budget and exhaust time before temp removal.** `scripts/network/online-recovery-smoke.ts:29` only flips `timedOut`/aborts readiness at 80 seconds; it does not cancel in-flight driver commands. `:244` then shuts applications down sequentially, each with a fresh five-second request budget (`:51`), and `kill()` can issue another fresh five-second resources request (`:77`). With two unresponsive live apps, those requests alone can consume twenty seconds after entering cleanup. Runtime disposal then adds its own independent waits (`scripts/network/online-app-runtime.ts:50`, `:56`, `:62`). Only process termination and directory removal use the shared deadline, so reaching removal after 90 seconds prevents the required cleanup attempt from completing. Thread the remaining absolute budget through driver requests and runtime disposal, reserve time for exact termination/removal, and cover multiple unresponsive apps with a focused deadline test. The existing timeout probe fires early with responsive app cleanup and does not exercise this case (`scripts/network/online-recovery-smoke.ts:144`).
