# Open-licence UI kits, icon sets, effect sheets and pixel fonts for FTLite

Scope: 2D top-down pixel-art couch co-op spaceship game, PixiJS 8, 960x540 internal resolution, 32 px tiles. Tone: scrappy civilian ship (FTL / Firefly). Research date: 2026-11-09. Every licence below was read on the primary asset page (kenney.nl, itch.io, opengameart.org, raw OFL.txt in google/fonts) unless flagged otherwise. OpenGameArt (OGA) pages return HTTP 403 to automated fetchers but were readable via curl with a browser user agent; the licence field, author, upload date and file list quoted below come from those page reads.

Licence shorthand used: CC0 = Creative Commons Zero (no attribution required, commercial OK). CC-BY = attribution required. OFL = SIL Open Font License 1.1. RFN = Reserved Font Name.

## Key Question 1: Which CC0 / CC-BY pixel UI kits (panels, bars, buttons, frames) exist in a sci-fi or neutral style?

### Takeaway
There are three strong CC0 pixel-art UI kits that fit a scrappy sci-fi HUD without attribution obligations: Kenney's "Pixel UI pack (750 assets)" (neutral, 2015), Buch's "Sci-fi User Interface" + "UI pieces" (CC0, DawnBringer palette, fill bars/windows/checkboxes), and Zed Hanok's LCARS-style "Sci-fi UI Pixel Art" (CC0, 24x24 tiles). The best purpose-built sci-fi HUD kit with hull/shield/energy bars and 16x16 icons is heyheythere's "Pixel UI Sci-Fi Free" but it is CC-BY 4.0 and needs a credit line. Kenney's vector-style "UI Pack - Sci-Fi" is CC0 but is not pixel art.

## Key Question 2: Which icon sets cover ship systems and hazards (fire, oxygen, breach, power, repair, medical, door, weapons, sensors)?

### Takeaway
No single open pixel-art icon set is themed on spaceship systems. The practical pairing is game-icons.net (about 4,180 vector SVG icons, CC BY 3.0, with explicit flame/fire/blaster icons) for console-screen glyphs plus Nikoichu's "1-bit Pixel Icons" (1,476 CC0 16x16 icons including Medicine, Warfare and Tools sections) and Kenney's 1-bit input prompts (CC0, 16x16) for per-player button prompts. Fire/oxygen/breach hazard glyphs at 16 px will probably need to be drawn or adapted.

### Inferences
- game-icons.net SVGs can be rasterised at 16 or 32 px with nearest filtering and a 1-bit threshold to approximate pixel icons for console screens; because the licence is CC BY 3.0 the credits screen must list the specific icon authors (e.g. "Icons made by Lorc, Delapouite and sbed. Available on https://game-icons.net").
- A FTLite-specific hazard glyph set (fire, O2, breach, power, repair wrench, medkit, door, weapons, sensors) is small (about 10 icons at 16x16) and is cheaper to draw in-house than to license; the open sets above cover prompts, medical, tools and weapons but not oxygen, hull breach or door glyphs.

### Gaps
- No open pixel icon set explicitly containing oxygen, hull-breach, door or sensor glyphs was found on OGA or itch in this pass.
- game-icons.net offers no official bulk PNG/ZIP download yet (roadmap item), so icons must be exported individually or via the Studio tool.

## Key Question 4: Which pixel fonts are OFL or CC0, legible at 8-16 px, and permitted for embedding in a shipped game?

### Takeaway
All five Google Fonts pixel families checked (Press Start 2P, VT323, Silkscreen, Pixelify Sans, Tiny5) are SIL OFL 1.1 and may be embedded in a commercial game; only Press Start 2P declares a Reserved Font Name, which matters if the font is converted to a bitmap atlas (a format change the OFL FAQ "normally" treats as a modification). CC0 itch fonts m5x7 (Daniel Linssen) and monogram (datagoblin) avoid the RFN issue entirely, and monogram even ships a ready bitmap PNG+JSON.

### Cited Findings

OFL licence terms:
- OFL FAQ 1.4: fonts may be bundled with games and commercial software ("Yes, you can do this with both the Original Version and a Modified Version"); 1.3: only the font portions must stay OFL, the program's own code need not be open; 1.5/1.6: fonts cannot be sold by themselves; 3.3: derived fonts may be included in a larger sold package; 1.20: you must include "the copyright statement, the license notice and the license text". — [OFL FAQ](https://openfontlicense.org/ofl-faq/)
- OFL FAQ on Reserved Font Names: 5.3 "you cannot use the Reserved Font Names in any way to identify the font to the user" of a Modified Version; 3.1 a modified version must change the internal name "to your own font name" even for small changes; 2.2 a format change "normally is considered modification, and Reserved Font Names (RFNs) cannot be used"; the FAQ does not address bitmap/texture-atlas conversion for games specifically. — [OFL FAQ](https://openfontlicense.org/ofl-faq/)

PixiJS 8 notes on bitmap fonts:
- BitmapText draws glyphs from a pre-generated texture atlas rather than rasterising each string, allowing "tens of thousands of text objects with minimal overhead"; it loads AngelCode BMFont and MSDF-compatible .fnt and .xml files via Assets.load, and the guide recommends AssetPack to generate MSDF/SDF fonts from .ttf/.otf for resolution-independent text; BitmapText.resolution cannot be changed at runtime (handled by the BitmapFont); bitmap fonts are bound by texture size so CJK/emoji-heavy sets are better served by Text or HTMLText. — [PixiJS 8 BitmapText guide](https://pixijs.com/8.x/guides/components/scene-objects/text/bitmap)
- BitmapFont.install generates a font dynamically from a TextStyle with options including name, style, chars (ranges such as [['a','z'],['A','Z'],['0','9']]), resolution, padding and textureStyle (example shows scaleMode: 'nearest'); uninstall(name) frees it. — [PixiJS BitmapFont API](https://pixijs.download/release/docs/text.BitmapFont.html)
- PixiJS text guide: choose Text for fidelity, BitmapText for throughput (thousands of changing labels; register a font first with BitmapFont.from or Assets.load), HTMLText for rich markup; avoid BitmapText when you need frequent font/size changes. — [PixiJS 8 Text guide](https://pixijs.com/8.x/guides/components/scene-objects/text)
- In v8, scale modes are the strings 'nearest' and 'linear' and can be set on the texture source (texture.source.scaleMode = 'nearest'); community threads report that setting scale mode on a Text object's texture no longer works in v8 because the texture properties differ. — [html5gamedevs thread](https://html5gamedevs.com/topic/55669-using-scalemode-strings-on-pixi-v8); [PixiJS GitHub issue 6884](https://github.com/pixijs/pixi.js/issues/6884)

### Inferences
- For a 960x540 HUD rendered at integer scale, a true bitmap pixel font (m5x7 at 16 px, monogram at its native 5-px-wide grid, Press Start 2P at 8/16 px, Tiny5/Silkscreen at 8-10 px) with a BitmapFont using scaleMode 'nearest' and integer font sizes will stay crisp; MSDF fonts are the wrong tool here because they are designed for smooth scaling, not pixel-snapped glyphs.
- Pre-baking a .fnt atlas (BMFont/AngelCode) from an OFL TTF is a format change, so to be safe name the exported font something other than the RFN (e.g. "FTLite HUD 8" rather than "Press Start 2P"), ship the OFL.txt and copyright line in the credits, and prefer the RFN-free families (VT323, Silkscreen, Pixelify Sans, Tiny5) or CC0 fonts (m5x7, monogram) where this is a concern.
- monogram's bitmap PNG+JSON is close to drop-in for PixiJS (convert the JSON to BMFont XML/.fnt or use BitmapFont.install from the TTF); m5x7 renders cleanly at 16 px via BitmapFont.install with 'nearest'.
- Fonts from dafont/fontspace were not individually checked; many there are "free for personal use" only, so treat them as unverified unless the licence file says OFL/CC0.

### Gaps
- fonts.google.com FAQ and specimen pages render via JavaScript and could not be read; licence facts come from the OFL.txt files in the google/fonts repository instead.
- Legibility at exactly 8 px vs 16 px for each family was not measured; pixel-per-em values (Press Start 2P 8 px, m5x7 nominal 16 px, monogram 5 px wide) come from the authors' pages, and Tiny5/Silkscreen/VT323 native sizes were not confirmed on primary pages.
- No official PixiJS 8 documentation was found covering pixel-perfect BitmapText (roundPixels + nearest) specifically; guidance above is from the API example (textureStyle scaleMode 'nearest') and community threads.
- Whether a BMFont atlas counts as an OFL "Modified Version" is not addressed by the OFL FAQ for game pipelines; the inference above is conservative.
