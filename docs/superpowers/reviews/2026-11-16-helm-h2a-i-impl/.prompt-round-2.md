### [P3] R1-F2 runRematch does not check that the scripted commands were applied, unlike runDuel
runDuel throws when any scripted command is not applied, so the duel golden can never pin a run in which the script is being rejected. runRematch drops the results of both rounds' scripted steps. Round 2 runs with every tick offset by baseTick, so a stale-tick or not-at-weapons rejection there would be blessed into the golden without any error. · tests/helpers/scriptedDuel.ts:L44-50 (runDuel's applied-status check) against L99-100 (runRematch: `stepDuelTick(d, input); recordTick(t, d, input)` with the results discarded). · Round 2 is the only part of the rematch golden that no other pinned artifact covers. A silently rejected script would make it pin degenerate behaviour. · In play(), keep stepDuelTick's results and throw on any status other than 'applied', with the same message runDuel gives, before recordTick.
