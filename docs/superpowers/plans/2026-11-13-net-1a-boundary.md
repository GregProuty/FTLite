# Net-1a: The Offline Authority Boundary Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run unchanged couch gameplay through a headless authority and local loopback, with explicit commands, client-owned menu state and an independent clock.

**Architecture:** Clients and host-side bot agents derive tick T input from completed state T−1. The authority admits inputs before tick entry, executes without client callbacks, and publishes lossless state plus reliable results/events. One temporary `legacyCardInput` bridge supports unmigrated controls and is deleted before acceptance.

**Tech Stack:** Existing TypeScript 5.8, Electron 37, Pixi 8, bitecs 0.4, zod and Vitest 3. No new runtime dependency or network service.

**Spec:** [Net-1 foundations](../specs/2026-11-13-net-1-foundations-design.md), including amendments 1–7; [approved Net-0](../specs/2026-11-13-networking-decision.md). Planning baseline: `0a47e50`. Read both before execution. This document changes no implementation and claims no test results.

## Global Constraints

- “No runtime mid-tick client handshake is permitted.” Clients read completed publications only; missing clients never prevent a tick.
- “No gate floor is ever lowered.” Preserve strategy, RNG order, tuning and scenario setup; trace every changed figure to its first differing action/tick.
- “The single SIM_VERSION bump and bless happen once, at the end of Net-1a, after traced parity.” Only the saved-hash assertion may fail after the first canonical shape change (task 5); tasks 1-4 require exact golden hashes; all gameplay differential tests and all other assertions must pass.
- Keep 60 Hz simulation, 120 ticks maximum per pump, retained debt, 0.5 stick threshold and eight-tick repeat. A five-second active stall owes 300 ticks across multiple passes.
- Closed 26-kind Command union from spec §5; `moveTo` returns terminal `unsupported`. No mouse UI/pathfinding/prediction/sockets/cloud integration.
- Reliable queue cap 1 MiB/direction; loopback maxDatagram 65,536; at most 16 commands/player/tick and 256 pending/control commands/link; retain last 256 command results/player.
- Use lossless Float64 input/state values, stable gameplay target IDs and existing gameplay helper predicates. Never use raw ECS IDs as wire identity.
- Exactly one named temporary runtime bridge: `legacyCardInput`. Each family removes its branch; final ingress rejects raw presses. Test-only golden translation is separate.
- Net-1b owns entity recycling, per-viewer HUD, portable replay/checkpoint v2 and real-browser determinism harness. Net-1a owns timer/link teardown, correct current-shape snapshots, bounded in-memory crash traces and AST guard.
- Original art only; no new art in this milestone. Preserve unrelated workspace files and do not commit them.

## Review Focus

1. **Queued old-run input after restart:** it must not move or spend resources in the new run (tasks 2, 3, 11).
2. **Two local crew over one link:** latest input for one player must not replace the other player's input or allow unowned IDs (tasks 2, 3).
3. **Blur/disconnect during held repair and queued Confirm:** neutralize held input without losing pre-pause clock debt or inventing repeated commands (tasks 4, 5).
4. **Selection and target replacement in one tick:** ordered selection/fire is explicit; a destroyed/reused target must not redirect a later command (tasks 7, 8).
5. **End event alongside a coalesced state update:** save progress and play completion once; no event replay into the next run (task 11).

Common interfaces established by tasks 2–4:

```ts
// Imported types named here are declared in contracts.ts or the existing sim modules.
type TickInput = {
  held: readonly HeldInput[];
  commands: readonly CommandEnvelope[];
};
type ClientActions = { held: HeldFrame[]; commands: CommandEnvelope[] };
type CardUiState = {
  runId: RunId;
  players: { nextSequence: number; heldDir: number; repeat: number;
    pendingVote: { event: EventRef; choice: number } | null }[];
  stations: { rowKey: string | null; page: 'main' | 'upgrades' }[];
  groupBar: boolean[];
};
type CardRow = { key: string; enabled: boolean; text: string;
  action: Command | null }; // UI actions such as BACK use controller dispatch by key
createLoopbackHarness(): { createSession(): Session; drain(): void };
encodeMessage(message: ClientMessage | AuthorityMessage): Uint8Array;
decodeMessage(bytes: Uint8Array): ClientMessage | AuthorityMessage;
createAuthority(deps: AuthorityDeps): Authority1a; // spec §3, Net-1b methods deferred
createClientRun(link: Link, owned: readonly PlayerId[]): ClientRun;
translateTick(view: SimState, ui: CardUiState,
  frames: readonly InputFrame[], tick: number): ClientActions;
stepCommands(state: SimState, input: MigrationTickInput): readonly CommandResult[]; // becomes TickInput in task 11
```

`ClientRun` exposes `receive` through its link subscription, `state(): SimState | null`, `ui: CardUiState`, `send(actions: ClientActions): void`, and `dispose(): void`; its state is exclusively the replica. Actual sequence assignment belongs to the controller/client producer (one sequence stream/player), not UI components. `translateTick` receives that producer context through CardUiState, including run ID and next sequence initialized from authoritative high-water marks. `AuthorityDeps` is the spec's clock/scheduler/layout resolver/crash callback, plus synchronous optional `beforeControls():void` at every pump entry and `beforeTick(nextTick:number, tickTimeMs:number):void` before each queue freeze, never inside step. Its return value is ignored; it cannot return a Promise or block on a client. The authority owns the driver and always proceeds after this opportunity; absent/failed producers contribute no action. Add no renderer dependencies. `checkpoint/restore` portable contracts are documented but not falsely implemented as durable APIs in Net-1a.

Use `Authority1a = Pick<Authority, 'attach' | 'start' | 'pump' | 'dispose'>` for this milestone's public return type; the final spec's checkpoint methods are not throwing placeholders. ClientUiState in the spec is the app's wrapper around CardUiState plus device labels. Held-frame sequence counters are separate from command nextSequence. Define Admission as `{status:'queued'} | {status:'duplicate'|'rejected'; result:CommandResult}`; exact reason codes include wrong-run, unowned, malformed, expected-sequence, stale-tick, over-capacity, invalid-seat, stale-target, unavailable and unsupported.

Migration dependency rule: when a family stops reading canonical cursor/page fields, migrate **all its readers in that same commit**, including HUD helpers, test drivers and bot policy. Introduce the pure `botFrame(view, ui, player)` adapter in task 3 and migrate its UI readers in tasks 5-9; unmigrated actions still use legacyCardInput. Task 3 establishes host-side client orchestration; task 10 finishes bot extraction and proves replica equivalence; it is not permission to leave bot compilation/tests broken until then. Do not create a synthetic SimState with fake cursor fields to keep old code running. The single shared translator owns migrated UI memory. Staging bot reads this way changes no policy or cadence.

`ClientMessage` variants: held, command, auxiliary callout, and the explicitly temporary legacy input envelope. `AuthorityMessage`: state, result, event. Bootstrap binds players via `attach`; authentication is not invented for loopback. Use protocol version 1, current sim version and digest of canonical gameplay/layout content for compatibility. The digest includes gameplay constants and catalogs, not just layout; compute it with existing build tooling and test a changed weapon definition invalidates compatibility. Do not add native hashing dependencies.

- **Catch-up opportunity:** Keep the spec's authority-owned `pump`. The driver calls authority with `(nextTick,tickTimeMs)` once per due tick. Authority calls the injected synchronous `beforeTick` outside tick execution, then freezes/adjudicates ingress, steps and publishes. Test an absent and delayed producer on this same path.
- **Clock epochs and pause:** Tick deadlines are their original wall-clock deadlines within active epochs. Debt retains those deadlines across pause; new deadlines after resume exclude the paused interval. Input at resume cannot apply to historical debt. Task 4 implements setPaused, pause-owner/control revision and the trusted lifecycle adapter together. `setPaused.requestedTick` must equal the next unexecuted tick at admission, even while paused; it uses the normal player command sequence but the control phase runs at pump entry without advancing sim. On pump entry accrue active time through the boundary before applying controls; pause retains all owed ticks and executes none until resume. Pause wins conflicting states in one drain. Test pause after a 5000ms stall: zero ticks while paused, then 120/120/60 on resume, with no ten-second paused debt; same-boundary pause/resume; focused Confirm forwards to the first eligible gameplay tick after resume. Lifecycle ordering is journalled. Remove app/loop.ts and its obsolete tests in task 11 after clock cases have moved.
- **Held admission and run identity:** Composition injects a monotonically increasing run counter; no Date/random in authority. Held frames require matching run, owned player, raw finite axes with each component in [-1,1], without a unit-vector-length rejection, safe nonnegative tick, and strictly increasing per-player held sequence starting at 1; accept only the next unexecuted tick. Reject stale/future frames without replacing current held state; gaps are allowed on this latest stream, duplicates/older frames ignored. Clients send raw axes, not pre-normalized vectors. Preserve clampIntent math in the sim; each consumer derives its normalized value from the raw frame, never from an already normalized result. Tasks 3-4 bridge axes come from that same raw held frame. Test (0.8,0.8) and one-ulp boundary cases against baseline positions/hashes so double normalization or strict length rejection cannot creep in. Held counters are independent of command IDs, bounded to safe integers, and never wrap within a run. Neutralize on suspension. Pin these cases in task 3.
- **Crash journal from task 3:** Capture a complete current-shape Snapshot and admission watermarks/control state every 300 ticks, then retain bounded tick records containing resolved held frames, admitted semantic/bridge envelopes and results plus ordered controls. Record the faulting frame before execution. The test-only crash replay uses the same phase executor, replays successful frames up to the fault, and compares the pre-fault hash; separately asserts watermarks/results/control order. Adapt session crash tests in task 3, not task 11. Task 11 removes bridge journal entries; durable replay/save v2 remains deferred.
- **Content digest:** Build a sorted manifest of repository-relative paths and SHA-256 hashes of normalized-LF UTF-8 source bytes for every `src/renderer/src/sim/**/*.ts` and `sim/**/*.json`, plus `src/shared/intent.ts` and wire contracts/codec. This deliberately invalidates on harmless source edits too, but covers all gameplay constants/catalogs/helpers without a manually incomplete list. Test determinism under filesystem enumeration order and invalidation on weapon definition/layout/tuning changes. Do not hash git metadata or depend on runtime Node crypto.

## Execution and verification convention

Each task follows the five checked steps below: failing tests, confirm failure, minimal implementation, verification, scoped commit. Run targeted tests first, then `npm test` and `npm run typecheck`. Task 3 onward also runs `npm run build` before its commit and a short playable smoke check when the UI changed. Inspect full test output; an exit code of 1 is not automatically the approved exception.

Only after the first canonical shape change in task 5, `tests/golden.test.ts` → `matches the golden hashes (run npm run bless to update deliberately)` may fail between shape changes and the final bless. Do not skip that test, exclude its file, bless early, or tolerate its encode/decode/version assertions failing. Record the exception and first hash divergence in the task's evidence. Every other test, typecheck and build must pass. The gameplay trace suite must pass even on those intermediate commits.

Stage the minimum listed files plus verified readers/callers of the changed interface, inspect `git diff --cached --stat`, and commit with the task's message. Do not use `git add .`. Detailed gate figures go in `docs/gates.md` as implementation progresses. Stop on a floor regression; do not repair it with tuning.
