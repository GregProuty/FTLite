# W-4a: the Hound's loadout, the autocannon and the Weapons keys — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the Hound (the `cutter` class) its W-4 loadout: pew pew, the Valkyrn's gun as an autocannon whose bars set its fire interval, and the torpedo; the beam leaves the Hound. Autocannon rounds wear and break rocks, Science's weak frequency boosts both guns, `pewFire` loses its aim (it fires along the nose until W-4b's turret), and the Weapons seat gets its new keys: A/D or 1/2/3 select, W/S power the selected weapon, LMB fires the selected weapon (the autocannon while held), 4/5/6 tune the guns. The scripted gunner spends the spare reactor bar on the autocannon and keeps a stand-in pew rule until W-4b's AUTO.

**Architecture:**

- **Defs first.** `GunDef` and `PewDef` gain the W-4 fields (`turret`, `intervalByBars`, `rock`, `weakHitsPerLayer`). The Valkyrn's `GUN`, `PEW` and `HUNTER_PEW` get nulls. New `AUTOCANNON` and `HOUND_PEW` carry the Hound's values, and `CUTTER_CLASS` takes them with a null laser. Every rule change is fenced on these fields (`turret !== null`, `rock !== null`, `weakHitsPerLayer !== null`) or on `hasTurret(cls)`, so the Valkyrn and the Hunter take today's branches byte for byte.
- **No new hashed state in W-4a.** `pewTurret`, `gunTurret` and `gunsManual` are W-4b's. Two seams stand in for them: `gunInterval(state, i)` (row 0 of the interval table by the autocannon's bars) and `gunAimFine` / `pewAimFine` (the nose). W-4b changes only those bodies.
- **The wire.** `pewFire` becomes `{ kind: 'pewFire' }` and sets `ShipInput.pewTrigger`. `HeldInput.weaponSel` (0..2) joins every held schema and the authority's expiry and pause lists. The step reads `gunHeld` on a turret class only when `weaponSel === 1`.
- **The app.** A pure helper module (`app/duel/weaponsSeat.ts`) holds the seat's selection, power, LMB and frequency rules, and both runtimes call it from a new Hound Weapons-seat branch. The laser class's Weapons-seat branch stays as it is (the laser fit on the Hound layout through `cls`, spec §13.4). The keyboard splits the digit keys into `freqKeyTo`, `gunFreqKeyTo` and `selectTo`. The scene reports the held left button over the open map as `MapRequests.trigger`.
- **The UI.** `WeaponsStation` renders a Hound variant (PEW PEW, AUTOCANNON, TORPEDO, the selected one framed hot) when the panel carries `autocannon`. The laser class keeps today's block.
- **The tests.** The beam's own tests are ported to the laser fit first (Task 2), while master's Cutter still has the beam, so they are green before and after the loadout flips.

**Tech Stack:** TypeScript 5.8 (strict, `noUncheckedIndexedAccess`), Vitest 3.2 (+ jsdom for UI tests), React + zustand (console), zod 3 (wire), Pixi.js (map), Electron/electron-vite, the golden scripts under `scripts/golden/`.

**Spec:** `docs/superpowers/specs/2026-11-19-w4-weapons-controls-design.md` (converged at 96c8c2dd). // W-4 spec §13.4: the Hunter's own play is unchanged by W-4. A duel against a crew parked still at its spawn (its body
// written every tick, nobody at its consoles), on the Valkyrn class (W-4 leaves it bit-identical by its fences), hashed
// per tick on the Hunter's body, weapons and brain and on the crew ship's hull, shields and rooms only, so the new crew
// fields cannot reach the digest. The digests were recorded on the branch at W4_BASE (master's code, SIM V).
import { createHash } from 'node:crypto';
import { describe, expect, it } from 'vitest';
import { ShipClass } from '../src/renderer/src/sim/tactical/defs';
import { stepDuel } from '../src/renderer/src/sim/tactical/duel';
import { createTacticalState, Outcome } from '../src/renderer/src/sim/tactical/state';
import { UNCREWED_INPUT } from '../src/renderer/src/sim/tactical/weapons';

const TICKS = 3000;
const DIGESTS: Readonly<Record<number, string>> = { 1: '', 2: '', 3: '' };

function run(seed: number): string {
  const st = createTacticalState(seed, 2, ShipClass.Valkyrn), h = createHash('sha256'), c = st.ships[0]!;
  const home = { x: c.x, y: c.y, heading: c.heading };
  for (let k = 0; k < TICKS && st.outcome === Outcome.Running; k++) {
    Object.assign(c, { x: home.x, y: home.y, vx: 0, vy: 0, heading: home.heading, headingAcc: 0 });
    stepDuel(st, UNCREWED_INPUT);
    const e = st.ships[1]!, s = st.systems[1]!, b = st.hunter, crew = st.systems[0]!;
    h.update(Buffer.from(Float64Array.from([
      e.x, e.y, e.vx, e.vy, e.heading, e.headingAcc, Number(e.active),
      s.hull, s.shields, s.shieldClock, s.laserCharge, s.laserHold, s.laserBurst, s.lock, s.pewCharge, s.magazine, s.magazineClock, s.shots, s.laserHits, s.pewShots, s.pewHits, s.missilesLaunched, s.missileHits,
      b.mode, b.room, b.timer, Number(b.working), b.fireAt, b.lastLaunch, b.pewBurst, b.pewClock,
      crew.hull, crew.shields, ...crew.rooms
    ]).buffer));
    h.update(JSON.stringify(st.events.filter((v) => 'ship' in v && v.ship === 1)));
  }
  return `${st.tick}:${h.digest('hex').slice(0, 16)}`;
}

describe("the Hunter's own play is unchanged by W-4 (W-4 spec §13.4)", () => {

/** W-4 spec §9: why weaponPower {slot, delta} would be refused now, or null: NO BAR (−1 at 0), NO FREE BAR (+1 with every
 *  usable bar spent), MAX (+1 at the slot's top: 3, or 4 with the overdrive bar and no other 4th). The app's W/S flash. */
export function weaponPowerRefusal(d: DuelState, slot: number, delta: number): 'NO BAR' | 'NO FREE BAR' | 'MAX' | null {
  const sys = d.tactical.systems[0], t = trimmedWeaponPower(sys), now = t[slot]!;
  if (delta === -1) return now === 0 ? 'NO BAR' : null;
  const usable = weaponBarsUsable(sys), spent = t[0]! + t[1]! + t[2]!;
  const top = usable > SYSTEM_MAX[DuelSystem.Weapons]! && !t.some((b) => b > WEAPON_BAR_MAX) ? WEAPON_BAR_MAX + 1 : WEAPON_BAR_MAX;
  return spent >= usable ? 'NO FREE BAR' : now >= top ? 'MAX' : null;
}
/** Spec §10.3 (Task 9a): apply weaponPower {slot, delta} to the crew's allocation, or refuse it (weaponPowerRefusal). */

  for (let k = 0; k < t.length; k++) sys.weaponPower[k] = t[k]!;
  sys.weaponPower[slot] = t[slot]! + delta;

}
