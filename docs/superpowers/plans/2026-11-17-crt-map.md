# CRT map (the console screens as an amber ship display) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** When a player is at a console (the duel's Helm and Weapons maps, the dev flight view), the screen reads as a monochrome amber CRT on the ship: amber phosphor on dark glass, a bloom, scanlines, an aperture grille, a vignette, a slow flicker and a bezel, while friend and foe, damage, the lock, warnings, missiles, the arcs and the readout stay readable without hue.

**Architecture:** Pure modules carry the rules and are unit-tested without a renderer: `render/crt.ts` (where the CRT applies, the `full` / `subtle` / `off` setting and its storage, the effect strengths, the flicker wave, the bezel geometry), `render/tactical/crtTheme.ts` (the six-colour phosphor ramp, dash lengths, blink rates, the two-state `blink`), `render/tactical/dashModel.ts` (dashes, dots and hatches as segment lists), and the readout's new `emphasis` field set by `readoutRows`. The Pixi tactical layer always draws in the ramp (it is drawn only in console views), takes a presentation time for its blinks, and gets the bloom and noise filters through `setCrt`. React gets a `crt` flag on each frame's view, a `crt` store slice for the setting, a `CrtContext` that the console overlays read, one glow wrapper, and a `CrtScreen` overlay (scanlines, grille, vignette, flicker, bezel) placed after the banners and before the end card. `app/crtBoot.ts` reads the setting at boot and F10 cycles it in dev builds.

**Tech Stack:** Electron 37, PixiJS 8.19.0, pixi-filters 6.1.5 (new; `AdvancedBloomFilter`), React 19.3 with zustand 5, TypeScript 5.8, vitest 3.2.7 (node and jsdom environments).

**Spec:** `docs/superpowers/specs/2026-11-17-crt-map-design.md` (refined to convergence at fbba4da; refine run `docs/superpowers/reviews/2026-11-16-crt-map-spec/exchange.md`).

## Decisions

1. **The amber ramp is the spec's, unchanged.** The prototype screenshots (Helm and Weapons, `subtle` and `full`, side by side with the three references) read as an amber ship display at the spec's hexes: `glass` reads as the dark tube, `faint` grid lines sit just above it, `mid` labels and compass ticks are readable at 1920x1080, `main` and `hot` carry the bright strokes and the bloom. One role changed for a measured reason: **the Pixi lock label's inverse bar is a `mid` block, not `main`** (the readout's LOCK value keeps a `main` block). At `full`, a `main` block is over the bloom threshold, and the bloom washed over the lock label's thin native-size (16 px) glass glyphs until they were hard to read; a `mid` block stays under the threshold and the glyphs stay crisp (glass on mid is about 5.7 : 1). The React readout is not bloomed (only one CSS drop-shadow on the group), so its `main` blocks stay readable.

3. **Readout emphasis per row** (`ReadoutRow.emphasis?: 'good' | 'warn' | 'alert' | 'crew' | 'enemy'`, set by `readoutRows` beside today's tints; a row without one carries no `emphasis` key, so existing `toEqual` checks are unaffected):
   | Row | Emphasis |
   |---|---|
   | mode heading HELM / WEAPONS / ON FOOT | none (a heading: `main` text) |
   | ship heading (HOUND) | `crew` (`main` text) |
   | own HULL | `alert` at hull ≤ SHIP_HULL / 4, else none |
   | own SHIELD (pips) | `crew` (lit pips solid `hot`) |
   | WEAPONS / SHIELDS / ENGINES room rows | `good` at level 0 (OK, `hot`), `warn` at level 1 or 2 (DMG n, `hot`; the repair bar `hot`) |
   | HUNTER heading | `enemy` (an inverse bar: a `main` block, `glass` text) |
   | enemy HULL | `good` at hull ≤ SHIP_HULL / 4, else none |
   | enemy SHIELD (pips) | `enemy` (lit pips hollow `main`) |
   | ROOMS (enemy levels) | `warn` when any enemy room is damaged, else none |
   | LASER heading (Weapons) | none |
   | LOCK (Weapons) | `enemy` (the value on a `main` inverse bar) |
   | CHARGE (Weapons) | `good` when full and no missile flies (HOLD n.n, `hot`, bar `hot`), else none (bar `main`) |
   | MAG (Weapons) | none |
   | OTHER, the other's status | none |
   | OUTSIDE heading (interior) | none |
   | HELM, WEAPONS EMPTY; COASTING; MISSILE INBOUND (interior only) | `alert`; the interior has no CRT, so they keep their tints there |

   `crtRowLook(row, t)` (in `ReadoutPanel.tsx`): a heading is a row with an empty value, no pips and a label. Labels `mid` (headings `main`), values `main`, bars `main`; `good` and `warn` give a `hot` value and a `hot` bar; `alert` puts the value (a heading: the label) on an inverse bar whose block alternates `main` ↔ `hot` at `ALERT_BLINK_HZ` 2 Hz, text `glass`; `enemy` puts the value (a heading: the label) on a `main` inverse bar, except on a pips row. The inverse bar spans the row's ink: y + 5, 22 high; a value bar is the value's `textPx` width plus 4 each side, right-aligned with the value; a heading bar spans the panel's inner width plus 4 each side.

4. **Dash and hatch helpers** (`render/tactical/dashModel.ts`, pure): `dashLine(points: readonly number[], dash: number, gap: number, out: number[] = []): number[]` (a flat polyline in, a flat `[x1, y1, x2, y2, ...]` segment list out; the pattern continues across vertices; `out` is cleared first and returned); `dashCircle(x, y, r, dash, gap, out = [])` (chords; `n = max(1, round(2πr / (dash + gap)))` periods so the pattern closes evenly; a dash longer than a quarter turn is split at its middle); `isConvex(poly: readonly number[]): boolean`; `hatchSegments(poly, spacing, angle, out = [])` (lines on the screen's lattice `p · normal = k × spacing`, each clipped to a **convex** polygon by intersecting it with every edge and keeping the extreme points along the line, no Pixi mask). **Convexity of `wedgeSegments`:** room 0 is a triangle and rooms 1 and 2 are trapezoids (their half-width is linear in the forward coordinate), so all three are convex; `tests/dashModel.test.ts` asserts it, so no triangle split is needed. The layer strokes a segment list as one path (`moveTo`/`lineTo` per segment, one `stroke`). Reused arrays hold only lists consumed at once: **a list passed to `Graphics.poly` is kept by reference until the frame renders** (found in the prototype: reusing one array for every poly drew every ship as the last polygon), so each `poly` gets a fresh array, as today.

5. **`CrtContext` and the store slice.** `UiState.crt: CrtSetting` (default `subtle` from `createUiStore`), written by `setCrtSetting(store, crt)` (writes only a change). `DuelUiView.crt: boolean` and `FlightUiView.crt: boolean` (required; `scene.ts` sets `crtActive(view)`, `flightMode.ts` sets `true`, `duelProbeFixture` sets `false`). `CrtContext` value `{ crt: boolean; scale: CrtScale; now: number }` (now in seconds), default `CRT_OFF = { crt: false, scale: crtScale('off'), now: 0 }`. `CrtProvider({ crt, children })` reads the store's setting and `useNow(crt ? CRT_TICK_MS : 3_600_000)` with `CRT_TICK_MS = 125` (8 steps a second cover the 2 Hz blink edges and the flicker); with `crt` false it hands out the constant `CRT_OFF`, so its clock never re-renders the interior's overlays. Consumers: `Panel`, `Bar`, `ReadoutPanel`, `Banners`, `MapOverlay`, `FeelPanel`, `CrtGlow`, `CrtScreen` (`useCrt()`).

6. **Where the overlay and bezel live.** `ui/stage/CrtContext.tsx` (the context, `CrtProvider`, `useCrt`, `CrtGlow`) and `ui/stage/CrtScreen.tsx` (the screen effects and the bezel), beside `Stage`, `Panel` and `Box`. `DuelUi`: `<Stage><CrtProvider crt={duel.crt}><CrtGlow>{MapOverlay}{ReadoutPanel}{Banners}</CrtGlow><CrtScreen /></CrtProvider>{EndCard}{LatencyOverlay}</Stage>`; `FlightUi` the same with `FeelPanel` and no end card. `CrtGlow` renders a fragment (no wrapper) without CRT or glow, else one absolutely placed `div` with `filter: drop-shadow(0 0 Npx main@0.6×glow)`, N = max(1, round(3 × scale × glow)) CSS px. `CrtScreen` returns null without CRT, else one `Box(0, 0, INTERNAL_W, INTERNAL_H)` (the letterbox rectangle, `overflow: hidden`) holding: scanlines (`linear-gradient` 1 device px of black at 0.45 × scanline every 3 device px), the grille (vertical, 1 device px of black at 0.3 × mask every 3 device px), the vignette (`radial-gradient` clear to 55 %, black at 0.6 × vignette at the edge), the flicker (black at `crtFlicker(now, flicker)`, at most 5 % × strength) and the bezel (a `div` inset `BEZEL_PX` = 3 with corner radius `BEZEL_RADIUS` = 8, both scaled like `Panel`'s border, its outer spread shadow `#24170d` filling the band and corners and an inner black shadow). Pointer events are off through `Stage`.

7. **pixi-filters, not a custom filter.** `pixi-filters@6.1.5` (peer `pixi.js >= 8.0.0-0`) installed with Pixi 8.19.0, built by electron-vite and run in Electron 37: its `AdvancedBloomFilter` (imported from the `pixi-filters/advanced-bloom` subpath so the bundle takes one filter) gives the reference's bloom on the bright strokes, and Pixi's own `NoiseFilter` gives the grain. `render/tactical/crtFilter.ts` makes both once, on the first setting with a glow: bloom `threshold` 0.5 (so `main` and `hot` bloom and `mid` and below do not; the prototype's first try at 0.3 bloomed the whole map and washed the lock label), `bloomScale` 1 × glow, `blur` 4 × max(0.5, glow), `quality` 5; noise 0.08 × glow, its seed moved each frame from the presentation time. The layer sets `container.filterArea` to the screen once (the star tile is 2w × 2h) and attaches `[bloom, noise]` with a glow, `null` at glow 0. Constructing a Pixi filter needs `document`, so the filter test runs under jsdom (`tests/crtFilter.test.ts`).

8. **The tactical layer's interface.** `draw(d, c?, t?)` gains `t` (presentation seconds, default 0; the scene and the flight mode pass `performance.now() / 1000`, which runs while paused) and `setCrt(scale: CrtScale)` (a no-op for the same object; `crtScale` returns one object per setting). The scene and the flight mode call `layer.setCrt(crtScale(renderer.crt()))` every frame before `draw`. `Renderer` gains `crt(): CrtSetting` and `setCrt(setting)` beside `feel`/`setFeel`; `main.ts`'s `bootCrt(renderer, store)` (after `createUiStore` in `startApp`, `startFlight` and `startDuel`) installs it with a target that writes both the renderer and the store slice.

9. **Frame time** (spec section 5), measured in the prototype on this machine with the harness (the real duel scene and React UI, the Weapons map at 1920x1080, a laser hit every 0.4 s, both missiles in flight), GPU on, 10 s after a 2 s warm-up:

   |---|---|---|
   | off | 600, 16.70, 16.80 | 0.60, 2.10 |

The spec's literal bar "p95 at most 16.7 ms" cannot be met by any setting at a 60 Hz display, `off` included: the ticker's `deltaMS` is the vsync interval (16.67 ms) plus scheduling jitter (spec note 2). Task 7 checks it as: at least 590 frames in 10 s and p95 at most 1.1 × `off`'s p95 at each setting.

```ts
// The CRT look of the console screens (CRT map spec sections 1, 3, 4): where it applies, the strength setting and its
// storage (mirrors render/feel.ts: localStorage under CRT_KEY, read once at boot by app/crtBoot.ts, F10 cycles it in dev
// builds only), the screen-effect strengths, the flicker wave and the bezel geometry. Pure: no Pixi, no DOM.
import type { FeelStorage } from './feel';

/** The views a CRT can show: the duel's three views and the dev flight view. */
export type CrtView = 'helm' | 'weapons' | 'interior' | 'flight';
/** The console views (the Helm map, the Weapons map, the flight view) are amber CRT screens; the interior is not. */
export function crtActive(view: CrtView): boolean { return view !== 'interior'; }

export const CRT_KEY = 'ftlite-crt';
export const CRT_SETTINGS = ['full', 'subtle', 'off'] as const;
export type CrtSetting = (typeof CRT_SETTINGS)[number];
export const DEFAULT_CRT: CrtSetting = 'subtle';

/** Screen-effect strengths, 0..1 each. `off` zeroes them all; the amber palette, the blinks and the bezel stay. */
export interface CrtScale { glow: number; scanline: number; mask: number; flicker: number; vignette: number }

const SCALES: Readonly<Record<CrtSetting, CrtScale>> = {
  full: { glow: 1, scanline: 1, mask: 1, flicker: 1, vignette: 1 },
  subtle: { glow: 0.5, scanline: 0.5, mask: 0.4, flicker: 0.4, vignette: 0.7 },
  off: { glow: 0, scanline: 0, mask: 0, flicker: 0, vignette: 0 }
};

/** The strengths for a setting: the same object every call, so a caller can compare by reference. */
export function crtScale(setting: CrtSetting): CrtScale { return SCALES[setting]; }

/** A stored value back to a setting; anything unknown (or nothing stored) is the default. */
export function parseCrt(raw: string | null | undefined): CrtSetting {
  return (CRT_SETTINGS as readonly string[]).includes(raw ?? '') ? (raw as CrtSetting) : DEFAULT_CRT;
}

/** The F10 dev cycle: full, subtle, off, full. */
export function nextCrt(setting: CrtSetting): CrtSetting {
  return CRT_SETTINGS[(CRT_SETTINGS.indexOf(setting) + 1) % CRT_SETTINGS.length]!;
}

/** Reads the setting; a storage that throws (denied, private window) gives the default. */
export function loadCrt(storage: () => FeelStorage): CrtSetting {
  try { return parseCrt(storage().getItem(CRT_KEY)); } catch { return DEFAULT_CRT; }
}

/** Writes the setting; storage failures are ignored (the setting still applies for this session). */
export function saveCrt(storage: () => FeelStorage, setting: CrtSetting): void {
  try { storage().setItem(CRT_KEY, setting); } catch { /* storage unavailable or full */ }
}

/** The darkest the flicker gets, at strength 1: a few percent. */
export const FLICKER_DEPTH = 0.05;
/** The slow brightness flicker's darkening, 0..FLICKER_DEPTH x strength, from the presentation time in seconds. */
export function crtFlicker(t: number, strength: number): number {
  const w = 0.5 + 0.5 * Math.sin(t * 2 * Math.PI * 0.37) * Math.sin(t * 2 * Math.PI * 1.3);
  return FLICKER_DEPTH * strength * w;
}

/** The bezel on the letterbox rectangle, in internal pixels: its width and the radius of its inner edge's corners. */
export const BEZEL_PX = 3, BEZEL_RADIUS = 8;
/** Whether the rectangle lies inside the bezel's inner edge (a W x H rectangle inset by BEZEL_PX, corners rounded). */
export function insideBezel(x: number, y: number, w: number, h: number, W: number, H: number): boolean {
  const l = BEZEL_PX, t = BEZEL_PX, r = W - BEZEL_PX, b = H - BEZEL_PX, R = BEZEL_RADIUS;
  if (x < l || y < t || x + w > r || y + h > b) return false;
  for (const [px, py] of [[x, y], [x + w, y], [x, y + h], [x + w, y + h]] as const) {
    const cx = Math.min(Math.max(px, l + R), r - R), cy = Math.min(Math.max(py, t + R), b - R);
    if ((px - cx) ** 2 + (py - cy) ** 2 > R * R) return false;
  }
  return true;
}
```

```ts
// The CRT setting at boot (CRT map spec section 4), mirroring feelBoot.ts: read once from localStorage (a denied storage
// gives the default, subtle), and in dev builds only, F10 cycles full, subtle, off and saves the choice. No menu entry.
import { loadCrt, nextCrt, saveCrt, type CrtSetting } from '../render/crt';
import type { FeelStorage } from '../render/feel';
import type { KeySource } from './feelBoot';

/** Where the setting goes: main.ts's target writes the renderer (the Pixi filter) and the UI store's `crt` slice (React). */
export interface CrtTarget { crt(): CrtSetting; setCrt(setting: CrtSetting): void }

export function installCrt(target: CrtTarget, opts: { storage: () => FeelStorage; keys: KeySource; dev: boolean; log?: (message: string) => void }): void {
  target.setCrt(loadCrt(opts.storage));
  if (!opts.dev) return;
  opts.keys.addEventListener('keydown', (e) => {
    if (e.code !== 'F10') return;
    const next = nextCrt(target.crt());
    target.setCrt(next); saveCrt(opts.storage, next);
    opts.log?.(`crt: ${next}`);
  });
}
```

```ts
// Dashes, dots and hatches for the CRT map (CRT map spec section 2): PixiJS 8 Graphics has no dash style, so these build
// plain segment lists [x1, y1, x2, y2, ...] in screen pixels that the layer strokes as one path. Each writes into the
// array it is given (cleared first) so a frame allocates nothing. Pure: no Pixi.

/** Dashes along a polyline [x0, y0, x1, y1, ...]: `dash` on, `gap` off, the pattern carried across vertices. */
export function dashLine(points: readonly number[], dash: number, gap: number, out: number[] = []): number[] {
  out.length = 0;
  let on = true, left = dash;   // the current phase and the length left in it
  for (let i = 0; i + 3 < points.length; i += 2) {
    const x0 = points[i]!, y0 = points[i + 1]!, x1 = points[i + 2]!, y1 = points[i + 3]!;
    const len = Math.hypot(x1 - x0, y1 - y0);
    if (len === 0) continue;
    const ux = (x1 - x0) / len, uy = (y1 - y0) / len;
    let s = 0;
    while (s < len) {
      const step = Math.min(left, len - s);
      if (on) out.push(x0 + ux * s, y0 + uy * s, x0 + ux * (s + step), y0 + uy * (s + step));
      s += step; left -= step;
      if (left <= 1e-9) { on = !on; left = on ? dash : gap; }
    }
  }
  return out;
}

/** Dashes around a circle as chords, the pattern stretched so a whole number of periods closes it (at least one). */
export function dashCircle(x: number, y: number, r: number, dash: number, gap: number, out: number[] = []): number[] {
  out.length = 0;
  if (r <= 0) return out;
  const n = Math.max(1, Math.round((2 * Math.PI * r) / (dash + gap))), period = (2 * Math.PI) / n, onA = (period * dash) / (dash + gap);
  for (let k = 0; k < n; k++) {
    const a0 = k * period, a1 = a0 + onA, m = (a0 + a1) / 2;
    // A dash longer than a quarter turn (a tiny circle) is split at its middle so the chords stay near the circle.
    if (onA > Math.PI / 2) out.push(x + Math.cos(a0) * r, y + Math.sin(a0) * r, x + Math.cos(m) * r, y + Math.sin(m) * r, x + Math.cos(m) * r, y + Math.sin(m) * r, x + Math.cos(a1) * r, y + Math.sin(a1) * r);
    else out.push(x + Math.cos(a0) * r, y + Math.sin(a0) * r, x + Math.cos(a1) * r, y + Math.sin(a1) * r);
  }
  return out;
}

/** Whether a flat polygon [x0, y0, ...] is convex (every turn the same way; collinear points allowed). */
export function isConvex(poly: readonly number[]): boolean {
  const n = poly.length / 2;
  if (n < 3) return false;
  let sign = 0;
  for (let i = 0; i < n; i++) {
    const ax = poly[2 * i]!, ay = poly[2 * i + 1]!, bx = poly[(2 * (i + 1)) % (2 * n)]!, by = poly[(2 * (i + 1) + 1) % (2 * n)]!;
    const cx = poly[(2 * (i + 2)) % (2 * n)]!, cy = poly[(2 * (i + 2) + 1) % (2 * n)]!;
    const z = (bx - ax) * (cy - by) - (by - ay) * (cx - bx);
    if (Math.abs(z) < 1e-9) continue;
    if (sign === 0) sign = Math.sign(z); else if (Math.sign(z) !== sign) return false;
  }
  return sign !== 0;
}

/**
 * Hatch lines at `angle` (radians from +x), `spacing` apart, clipped to a convex polygon [x0, y0, ...] by line-polygon
 * intersection (no mask). The lines sit on the screen's lattice (p · normal a multiple of spacing), not the polygon's,
 * so neighbouring segments' hatches line up.
 */
export function hatchSegments(poly: readonly number[], spacing: number, angle: number, out: number[] = []): number[] {
  out.length = 0;
  const n = poly.length / 2, dx = Math.cos(angle), dy = Math.sin(angle), nx = -dy, ny = dx;
  if (n < 3 || spacing <= 0) return out;
  let lo = Infinity, hi = -Infinity;
  for (let i = 0; i < n; i++) { const c = poly[2 * i]! * nx + poly[2 * i + 1]! * ny; lo = Math.min(lo, c); hi = Math.max(hi, c); }
  for (let c = Math.ceil(lo / spacing) * spacing; c <= hi; c += spacing) {
    let tMin = Infinity, tMax = -Infinity, ax = 0, ay = 0, bx = 0, by = 0;
    for (let i = 0; i < n; i++) {
      const px = poly[2 * i]!, py = poly[2 * i + 1]!, qx = poly[(2 * i + 2) % (2 * n)]!, qy = poly[(2 * i + 3) % (2 * n)]!;
      const sp = px * nx + py * ny - c, sq = qx * nx + qy * ny - c;
      if ((sp > 0 && sq > 0) || (sp < 0 && sq < 0) || sp === sq) continue;
      const k = sp / (sp - sq), x = px + (qx - px) * k, y = py + (qy - py) * k, t = x * dx + y * dy;
      if (t < tMin) { tMin = t; ax = x; ay = y; }
      if (t > tMax) { tMax = t; bx = x; by = y; }
    }
    if (tMax - tMin > 1e-6) out.push(ax, ay, bx, by);
  }
  return out;
}
```

```ts
// The tactical layer's CRT filters (CRT map spec section 3): a bloom on the bright strokes (pixi-filters' AdvancedBloomFilter,
// the v6 line for PixiJS 8) and a faint animated noise (Pixi's NoiseFilter). Made once, on the first setting with a glow;
// with glow 0 the layer attaches none.
import { AdvancedBloomFilter } from 'pixi-filters/advanced-bloom';
import { NoiseFilter, type Filter } from 'pixi.js';
import type { CrtScale } from '../crt';

/** Bloom and noise at glow 1; each scales linearly with the glow strength. */
export const BLOOM_THRESHOLD = 0.5, BLOOM_SCALE = 1, BLOOM_BLUR = 4, NOISE = 0.08;

export interface CrtFilters { list: Filter[]; apply(scale: CrtScale): void; tick(t: number): void }

export function createCrtFilters(): CrtFilters {
  const bloom = new AdvancedBloomFilter({ threshold: BLOOM_THRESHOLD, bloomScale: BLOOM_SCALE, brightness: 1, blur: BLOOM_BLUR, quality: 5 });
  const noise = new NoiseFilter({ noise: NOISE, seed: 0.5 });
  return {
    list: [bloom, noise],
    apply(scale) { bloom.bloomScale = BLOOM_SCALE * scale.glow; bloom.blur = BLOOM_BLUR * Math.max(0.5, scale.glow); noise.noise = NOISE * scale.glow; },
    /** A new grain each frame from the presentation time. */
    tick(t) { noise.seed = (t * 7.31) % 1; }
  };
}
```

```ts
/** The enemy's blinking marker ring, as a multiple of the ship's radius (the shield rings start at 1.6). */

 *  flight view) and the presentation time in seconds (performance.now() / 1000) for the blinks. `reset` hides every text
 *  and clears every drawing until the next draw (a restart). `reseed` redraws the star field once for a new run seed (a
 *  restart), in the same Graphics; `starSeed` is the seed it shows. `setCrt` applies a CRT strength (a no-op when the
 *  same object is passed again). */
export interface TacticalLayer {
  container: Container; stars: Container;
  draw(d: TacticalDraw, c?: CombatDraw | null, t?: number): void;
  reset(): void;
  reseed(seed: number): void;
  starSeed(): number;
  setCrt(scale: CrtScale): void;
}

/** The star field for a run seed: STAR_COUNT stars in one w × h screen, from an xorshift (render-only randomness). */
export function starField(seed: number, w: number, h: number): { x: number; y: number; b: number }[] {
  let r = seed >>> 0 || 1;
  const rnd = (): number => { r ^= r << 13; r >>>= 0; r ^= r >>> 17; r ^= r << 5; r >>>= 0; return r / 4294967296; };
  return Array.from({ length: STAR_COUNT }, () => { const x = rnd() * w, y = rnd() * h, b = rnd(); return { x, y, b }; });
}
export interface TacticalLayerOptions {
  fontFamily: string; viewport: Viewport; seed?: number;
}
export const PAUSE_TEXT = 'PAUSED   ESC: RESUME';

export function createTacticalLayer(opts: TacticalLayerOptions): TacticalLayer {

  const container = new Container();
  const bg = new Graphics(), stars = new Graphics(), grid = new Graphics(), contours = new Graphics(), bodies = new Graphics(), arcs = new Graphics(), ships = new Graphics(), helm = new Graphics(), combat = new Graphics(), overlay = new Graphics();
  container.addChild(bg, stars, grid, contours, bodies, arcs, ships, helm, combat, overlay);
  const drawn = [grid, contours, bodies, arcs, ships, helm, combat, overlay];
  const mk = (size: number, tint: number, anchorX = 0, anchorY = 0): BitmapText => {
    const t = new BitmapText({ text: '', style: { fontFamily: opts.fontFamily, fontSize: size } });

  };

  const rows = Array.from({ length: GRID_LABELS }, () => mk(FONT_NATIVE, CRT.mid, 0, 0.5));

  // shifting it by the parallax offset (0..w, 0..h, minus one tile) always covers the screen with no gap.
  bg.rect(0, 0, w, h).fill(SPACE);

  };

    for (let k = 0; k <= n; k++) { const ang = from + ((to - from) * k) / n; pts.push(a.x + Math.cos(ang) * r, a.y + Math.sin(ang) * r); }
    pts.push(a.x, a.y);
    return pts;
  }
  /** A laser arc: the own arc a mid fill with a solid main edge; the enemy arc no fill and a dashed dim edge. */

    else segments(g, dashLine(arcOutline(a, from, to), DASH, GAP, seg), 1, CRT.dim);
  }

    else g.fill(CRT.glass).stroke({ width: 2, color: blink(t, ENEMY_BLINK_HZ) ? CRT.hot : CRT.main });   // in phase with the enemy ring
  }

  }
```

```ts
// duel. ?view=helm|weapons|interior|flight&crt=full|subtle|off[&perf=1]. The staged duel: the enemy close ahead, own rooms
// at damage 1 and 2, enemy rooms at 2 and 1, the lock on Shields, both missiles in flight (moved each frame so trails

import hound from '../../src/renderer/src/sim/ship/hound.json';
import { parseShip } from '../../src/renderer/src/sim/ship/schema';
import { createDuel } from '../../src/renderer/src/sim/duel/state';

import { createUiActions } from '../../src/renderer/src/ui/actions';

import { mountUi } from '../../src/renderer/src/ui/mount';
import { INTERNAL_H, INTERNAL_W } from '../../src/shared/resolution';

async function main(): Promise<void> {
  const q = new URLSearchParams(location.search), view = (q.get('view') ?? 'weapons') as 'helm' | 'weapons' | 'interior' | 'flight';
  const assets = await loadAssets('./assets/manifest.json');
  const renderer = await createRenderer(assets);
  const store = createUiStore({ onlineAvailable: false }), crt = parseCrt(q.get('crt'));
  renderer.setCrt(crt); setCrtSetting(store, crt);
  const actions = createUiActions({ store, single() {}, online() {}, pause() {} });

  await mountUi({ el: uiRoot, store, actions, menu: false });
  renderer.resize(window.innerWidth, window.innerHeight);
  const lb = computeLetterbox(window.innerWidth, window.innerHeight, INTERNAL_W, INTERNAL_H);
  setLayout(store, { scale: lb.scale, offsetX: lb.offsetX, offsetY: lb.offsetY, dpr: window.devicePixelRatio || 1 });
  const frames: number[] = [];
  renderer.app.ticker.add((t) => { frames.push(t.deltaMS); });
  if (view === 'flight') startFlightMode({ renderer, seed: 7, ui: createFlightSink(store) });
  else {
    const d = createDuel(parseShip(hound), 7), t = d.tactical, own = t.ships[0], foe = t.ships[1];
    foe.x = own.x + 240; foe.y = own.y - 170; foe.heading = 40;
    t.systems[0].rooms = [1, 2, 0]; t.systems[1].rooms = [2, 1, 0]; t.systems[0].lock = 1; t.systems[0].hull = Math.floor(SHIP_HULL / 4);
    placeMissile(t, 0, { x: own.x + 60, y: own.y - 40, vx: 160, vy: -90, heading: 16, headingAcc: 0, age: 0 });
    placeMissile(t, 1, { x: foe.x - 50, y: foe.y + 150, vx: -120, vy: 40, heading: 50, headingAcc: 0, age: 0 });
    const scene = createDuelScene(renderer, { seed: 7, pauseText: 'PAUSED', ui: createDuelSink(store) });
    let last = performance.now(), queued: ViewEvent[] = [];
    const source: DuelViewSource = {
      duel: d, seed: 7, prev: [], missilePrev: [], crewPrev: [],
      cameras: { helm: createCamera(own.x + 60, own.y - 40, 0.9), weapons: createCamera(own.x + 80, own.y - 60, 0.9) },
      epoch: () => 0, active: () => 0, view: () => view, otherStatus: () => 'AT WEAPONS', axes: () => ({ turn: 1, thrust: 1 }), steer: () => 0.5,
      alpha: () => 1, paused: () => false, drainEvents: () => { const e = queued; queued = []; return e; }
    };
    const trail = [0, 0];
    renderer.app.ticker.add((tk) => {
      const now = performance.now(), dt = tk.deltaMS / 1000;
      if (now - last > 400) { last = now; queued.push({ kind: 'laser', ship: 1, hit: true, stripped: false, room: 1, x1: foe.x, y1: foe.y, x2: own.x, y2: own.y }); }
      for (const i of [0, 1]) { const m = missileOf(t, i)!; trail[i]! += dt; if (trail[i]! > 1.6) { m.x -= m.vx * 1.6; m.y -= m.vy * 1.6; trail[i] = 0; } m.x += m.vx * dt; m.y += m.vy * dt; }
      scene.draw(source, dt, { banner: null, layerPaused: false, end: null });
    });
  }
  if (q.get('perf') === '1') {
    await new Promise((r) => setTimeout(r, 2000)); frames.length = 0;
    await new Promise((r) => setTimeout(r, 10000));
    const s = [...frames].sort((a, b) => a - b), at = (p: number): number => s[Math.min(s.length - 1, Math.floor(p * s.length))]!;
    (window as unknown as { perfResult: string }).perfResult = `frames ${s.length} median ${at(0.5).toFixed(2)} p95 ${at(0.95).toFixed(2)}`;
  }
  (window as unknown as { shotReady: boolean }).shotReady = true;
}
```

## Spec notes (problems found while planning; the spec is unchanged)

1. **The flight view's feel panel is not in section 1's consumer list** (`ReadoutPanel`, `Panel`, `Bar`, `Banners`, `MapOverlay`), yet section 2 says every colour of "the console overlays" in a console view is a ramp colour and the flight view is a console view. `FeelPanel` uses `Panel` (which turns amber) with theme text colours, so leaving it out would put white and blue-grey text in an amber panel. The plan gives it the CRT look (title and values `main`, labels and help `mid`; Decision 2).
2. **Section 5's pass bar "p95 at most 16.7 ms" fails at `off` too on a 60 Hz display.** `ticker.deltaMS` is quantised to the vsync interval (16.67 ms) plus jitter; the prototype measured p95 16.80 ms at `off`, `subtle` and `full` alike, with no dropped frame. The plan checks at least 590 frames in 10 s and p95 at most 1.1 × `off`'s (the spec's 10 % rule), and records an uncapped run for the headroom (Decision 9).
3. **Section 2 says the lock label is "an inverse bar (solid main, glass text)".** On the Pixi map at `full`, the bloom over a `main` block washed the thin native-size glass glyphs; the plan uses a `mid` block for the Pixi label (under the bloom threshold) and keeps `main` for the React readout's LOCK value (Decision 1).
4. **Section 2 does not give the lock brackets' colour or the alert blink rate.** The plan uses `hot` brackets and 2 Hz for the alert bar (the damage rate).
5. **Section 3 says "pixi-filters ... if its bloom works ... otherwise a custom glow filter".** It works (Decision 7). Constructing a Pixi filter needs `document`, so its unit test runs under jsdom; the colour test runs in node without filters.
6. **Section 4's `crtScale` lists five strengths; the noise is not one of them.** The plan scales the noise with `glow` (Decision 7), so `off` has none.
7. **Section 2 says "grid `faint`".** The plan draws the 500-unit major lines `dim` at alpha 0.5 and the 250-unit minor lines `faint`, so the major squares read apart from the minors; both are ramp colours.
