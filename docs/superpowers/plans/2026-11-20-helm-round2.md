# Helm round 2: a throttle that stays, a tap to cut, drag, and a gas charge — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The crew Helm on the Hound gets a throttle that stays where it is left, a tap of S (or of W in reverse) that cuts it to 0, reverse at 50 %, the old drag and stabilise back (stabilise now also under thrust), a fixed turn rate with no gas boost, a cold gas charge that empties and refills, no right-click heading and no Space auto-face at the player's Helm, a velocity ring on the map, a THR readout and a GAS bar on the console, a Settings value for the tap time, new hints, and SIM_VERSION 63 → 64.

**Architecture:**

- **The sim.** Three new hashed values in the helm module after `thrMille`: `thrCut` (the cut's latch), `gas` (0..720) and `gasIdle` (0..30). A new Helm command `throttleCut` is admitted in its own loop after `heading`'s. `crewHelm` (`sim/duel/step.ts`) clears the latch, ramps (no return to 0), clamps, then spends and refills the gas through one pure helper `gasTick` (`sim/duel/helmFlight.ts`) that the app's `crewAxes` also calls. `flyShip` loses the turn boost and gains `FlightTuning.stabiliseUnderThrust`; `CREW_FLIGHT` takes the drag branch again. The Hound's reverse is its own `HOUND_REVERSE_FRACTION`.
- **The scripted Helm** sends `throttleCut` when it wants no thrust and the throttle is set, and before any stand from the crew Helm.
- **The app.** The keyboard times W and S (a fake clock in tests) and emits one-shot `throttleDown` / `throttleTap`. Both runtimes record the throttle when a key goes down and send `throttleCut` on a tap from the right side. Online, the source predicts 0 while a cut is in flight and predicts the latch. The crew Helm stops sending `face` and `heading`, and its right button pans. The console gets a THR readout, a GAS bar and new hints; the map gets a 4 px ring at the velocity line's end; Settings gets "Throttle tap".
- **The close** follows the repo's bless pattern: the kind (b) re-picks, a same-version bless at 63 for the new behaviour, then SIM_VERSION 63 → 64 alone, proved by the canonical trace and the duel oracle per tick.

**Tech Stack:** TypeScript 5.8 (strict, `noUncheckedIndexedAccess`), Vitest 3.2 (+ jsdom for UI tests), React + zustand (console), zod 3 (wire), Pixi.js (map), Electron/electron-vite, the golden scripts under `scripts/golden/`.

**Spec:** `docs/superpowers/specs/2026-11-19-helm-round2-design.md` (converged after two review rounds; its review record is `docs/superpowers/reviews/2026-11-19-helm-round2-spec/`). /** Helm round 2 §3.3: one tick of the cold gas charge from the attendant's held axes (each −1, 0 or 1; both 0 with nobody
 *  at the Helm). In order:
 *  1. spend: the fore/aft axis (y), then the port/starboard axis (x), the order crewHelm reads them, each venting while
 *     `gas >= GAS_SPEND` and taking GAS_SPEND;
 *  2. the idle count: 0 on a tick either axis is held (vented or not), else one more, up to GAS_REFILL_DELAY;
 *  3. the refill: GAS_REFILL, to GAS_MAX, on a tick the idle count stands at GAS_REFILL_DELAY after step 2.
 *  So nothing refills while an axis is held. Integers in and out; `x` and `y` are the axes that vented. The step and the
 *  app's crewAxes both call it, so the prediction vents what the sim vents. */
export function gasTick(gas: number, gasIdle: number, heldX: number, heldY: number): { gas: number; gasIdle: number; x: number; y: number } {
  let g = gas;
  const y = heldY !== 0 && g >= GAS_SPEND ? heldY : 0;
  if (y !== 0) g -= GAS_SPEND;
  const x = heldX !== 0 && g >= GAS_SPEND ? heldX : 0;
  if (x !== 0) g -= GAS_SPEND;
  const idle = heldX !== 0 || heldY !== 0 ? 0 : Math.min(gasIdle + 1, GAS_REFILL_DELAY);
  if (idle === GAS_REFILL_DELAY) g = Math.min(GAS_MAX, g + GAS_REFILL);
  return { gas: g, gasIdle: idle, x, y };
}
