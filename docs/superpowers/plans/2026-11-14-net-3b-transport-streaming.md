# Net-3b Transport and Streaming Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Preserve the previously selected execution method; no new method selection is needed.

**Goal:** Connect the utility authority to a remote client over actual Chromium WebRTC, with bounded delivery, validated20Hz state streaming and separate100ms presentation.

**Architecture:** Generic byte transport in hidden sandbox windows; mode-owned state conversion at utility/client edges. An injected trusted signalling/ticket provider drives each attempt; Cloudflare provider and online UI arrive later. Extend existing host owner, not a second host window.

**Tech stack:** Existing TypeScript/Vitest/Electron37.10.3, native RTCDataChannel, no new native dependencies.

**Spec:** `docs/superpowers/specs/2026-11-14-net-3b-transport-streaming-design.md` refines approved `2026-11-14-net-3-internet-sessions-design.md` sections3/4/7/8. Builder findings: `docs/superpowers/reviews/2026-11-14-net-3b-builder-check.md`.

## Global constraints

- Work on isolated codex/net-3 at fc08a99; preserve owner master/Helm work and existing benchmark checkout. No cloud deployment/credentials/user profile.
- Session protocol2, SIM_VERSION35, snapshot/checkpoint2, strict replay2 and receive-time replay3. No bless, altered golden b87a0284, floors or timing ceilings.
- Existing strict/couch APIs and behavior remain default. Never gate an authority tick on client state/input.
- Generic transport/stream algorithms cannot import sector/ECS/gameplay schemas. Only mode adapters and explicit composition roots may do so.
- Byte caps include framing overhead. Every retained queue also has a count bound; cancellation invalidates pending async continuations.
- Tests use exact meaningful boundary cases and actual browser proof. Do not run broad gates after each task; focused tests/typecheck then final suite/acceptance/engines.

## Review focus

1. Valid state above the local65,536-byte JSON limit must reach streaming without increasing that limit (task4).
2. ACK sent after validation, not storage, and a synchronous close must never enable a producer (tasks3/4).
3. Lost delta/base ACK, large ordinary fallback and paused control must remain bounded and recover newest state (tasks1/3/4).
4. Late ICE/description work or cancellation cannot revive a replaced attempt or leave a process (tasks2/5).
5. Two concurrent peers, guest-only ownership and initial synchronous publication must work without cross-routing or dropped first sync (tasks5/6).

### Task 1: Bounded RTC framing and data-channel Link

**Interfaces:** contracts defines `PayloadClass = 'input'|'state'|'checkpoint'|'control'`, `PayloadMetadata = {class:PayloadClass;stream:string;sequence:number}` and `classify(bytes:Uint8Array):PayloadMetadata`. Two partial assemblies max,10s expiry; logical caps above; at most4096 queued/outstanding fragment records. No compression. Expose only bounded reasons.

### Task 3: Generic state images, deltas and bounded stream scheduling

**Files:** create `src/network/state/{imageCodec,sender,receiver,timeline}.ts`, tests `stateImage.test.ts`, `stateStream.test.ts`, `presentationTimeline.test.ts`.

**Interfaces:** `StateImage={sequence:number;tick:number;epoch:string;metadata:Uint8Array;values:Float64Array}`; bounded epoch128chars, metadata16KiB, full encoded image128KiB, finite values. `encodeFull(image):Uint8Array`, `encodeDelta(base,image):Uint8Array`, `decodeState(bytes,base?:StateImage):StateImage`; strict records include version, current sequence/tick/epoch, full value count, optional base sequence, checksum covering metadata and values. Full/delta/ACK/full-received/refresh and opaque records share a bounded generic outer envelope carrying a fresh per-connection transport ordinal. Image.sequence is not this ordinal: a refresh may resend the same image under a new transport ordinal. Sender/receiver own these counters for their outgoing packets; image encode/decode stays independent of that outer envelope. Encoded logical packets, including this envelope, obey task1 class limits. Transport ordinals are independent of command IDs; never reject valid semantic retries as duplicate transport traffic.

`createStateSender({send:(kind,bytes)=>void;latestPayloadLimit:number;clock:MonotonicClock;close:(reason)=>void})` exposes `publish(image:StateImage, immediate:boolean):void`, `receiveControl(bytes:Uint8Array):void`, `dispose():void`, `stats():{retainedImages:number;retainedBytes:number;resyncs:number;pendingOrdinary:boolean}`. `createStateReceiver({accept:(image:StateImage)=>'accepted'|'ignored'|'rejected';sendControl:(bytes)=>boolean;onAcknowledged?:(image:StateImage)=>void;clock;close})` exposes `receive(bytes):void`, `dispose():void`, `stats():{resyncs:number;retainedImages:number;retainedBytes:number}`. Receiver invokes optional onAcknowledged only after accepted validation, successful validated-state ACK send, and a final not-disposed check; task4 uses it for initial producer activation. Both retain <=64 images AND8MiB bytes, detached immutable baselines; no state ACK until accept succeeds and sendControl returns true. Wrong hash/missing base requests bounded full refresh (initial plus1/s), second invalid full closes. A stale image is ignored without ACKing it as accepted.
