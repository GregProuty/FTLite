# Net-3b: WebRTC transport and state streaming

Status: slice refinement of the approved Net-3 Internet Sessions design. User authorized continuing implementation after Net-3a. Protocol choices below are implementation decisions, not new product choices. No service deployment or two-machine readiness is claimed.

## Intent and approach

Connect the independent utility authority to remote clients through native Chromium WebRTC, stream validated state efficiently, and provide interpolation without modifying confirmed gameplay. Preserve synchronous couch and all offline formats. Net-3a source fc08a99 is the starting point on codex/net-3; owner master has independent Helm work and is not changed here.

The approved approach is native Chromium data channels in the hidden sandbox window with MessagePorts to utility/client. Native Node WebRTC adds packaging/ABI dependencies; visible-renderer authority violates independent timing. Neither is reopened. Net-3c supplies authenticated signalling/tickets/TURN; this slice takes an injected trusted signalling interface and tests a local broker. No pretend production authentication or hard-coded shared ticket.

## Transport contracts

A peer attempt is bound to protocol2, mode/schema/sim/content/layout/run identity, roomId, hostGeneration, local/remote connection IDs and seatGeneration. The trusted session owner supplies a short-lived one-use expected ticket, local ticket and expiry; peer labels alone never authenticate. Both peers exchange matching identity/ticket on the reliable channel before Link is exposed. The session owns ticket issuance/consumption across attempts; each attempt also refuses repeats. Never include tickets, SDP, candidates, addresses or ICE credentials in errors/stats/logs. Host is offerer; guest answers. Reject unknown or wrongly configured channels.

Use ordered reliable and unordered maxRetransmits0 data channels, no media. Cap SDP64KiB, candidate text4KiB, 64 queued ICE candidates before remoteDescription and128 total per attempt. Serialize async negotiation; check disposed/generation after every await. Late callbacks cannot recreate state. Setup deadline30s; explicit connection failure/close disposes listeners, timers, channels and peer connection. Production automatic reconnect belongs Net-3d, not this attempt primitive.

A generic framing layer carries logical payload class (input4KiB, state128KiB, checkpoint256KiB, control4KiB), stream key and strictly increasing per-stream sequence. Generic transport cannot parse gameplay. Inject mode/session payload classification; deny unsupported classes/directions. Reliable logical payloads fragment into at most min(16KiB, negotiated SCTP maxMessageSize) INCLUDING headers. Zero maxMessageSize means unbounded SCTP support, still use16KiB. Reject too-small negotiated limit. Latest never fragments; oversize latest state falls back to reliable full upstream. Reassembly admits at most2 bounded partial messages and expires each after10s; reject overlapping/duplicate/invalid offsets or lengths before allocating. Keep a fixed metadata/frame-count ceiling as well as bytes. No compression in this slice.

Reliable queued application bytes plus browser bufferedAmount <=1MiB, including frame overhead and outstanding queued fragments. Latest one replaceable slot per stream, <=16 streams; bound its browser send high-water so stale packets cannot accumulate. Drain finite work on bufferedamountlow with a scheduled continuation when needed; do not rely on a low event that cannot fire because already below threshold. Copy caller bytes. Close safely even inside callbacks/send. Stats are bounded/redacted RTT, loss, queues and direct/relay route, never raw getStats reports.

## State stream boundary

Introduce generic immutable StateImage {sequence,tick,epoch,metadata:Uint8Array,values:Float64Array}. Sequence/tick are safe integers. Epoch is a bounded mode-owned discontinuity key. Encode finite Float64 values losslessly; canonical -0 behavior must match existing hash. Metadata is opaque mode-owned bytes, capped16KiB, total encoded full image <=128KiB. Full/delta wire records include version, identity, value count and checksum over metadata plus values (not values alone). Parser bounds counts/lengths before allocations. Deltas carry sorted unique in-range changed indices and full current metadata, and refer to one acknowledged immutable image. Changed length/epoch requires full. Generic algorithms import no sector schema/ECS.

Host sends ordinary running state at every third completed tick (20Hz). Reliable initial/control/pause/end states bypass cadence; reliable mode transitions force full. Results/events are never delayed behind the cadence. Keep at most64 images and8MiB retained image bytes per peer; only an exact acknowledged sent image becomes a base. Eviction or missing base triggers full refresh, limited to one request/second plus the initial request. When delta is no smaller or cannot fit latest packet, send reliable full. At most one ordinary reliable full image may remain unacknowledged; retain only the newest pending ordinary publication. Only an exact full-received receipt for that complete full packet frees this ordinary slot; a newer accepted delta ACK must never free it while the old full is still queued on the reliable channel. Receiver emits full-received after bounded structural full decoding, even if the image is stale or fails checksum/mode validation; this confirms transport retirement only. Validated-state ACK remains separate and is the only baseline/production acknowledgement. Deltas can continue at20Hz against an acknowledged base. Initial/control/end fulls bypass this ordinary slot but remain under reliable budgets. Large full fallback can therefore be limited by RTT under backpressure; this is deliberate, not a promise of20Hz for oversized state. No input waits on state acknowledgement inside a tick.

Client rejects stale/duplicate sequence without restoring older state, reconstructs without mutating baseline, checks checksum and mode validation, then delivers confirmed full publication to the existing client and ACKs only after acceptance. Initial full ACK gates human production. Bad hash/missing base causes one bounded refresh; a repeated invalid full closes. Maintain separate policies for recoverable transport loss and malformed/unauthenticated packets (close). Reliable results/events carry a mode-edge presentation floor from the authority boundary: requiredPublicationSequence, because pause controls can complete without increasing tick. They wait for that confirmed publication before presentation; producer reconciliation can still consume results early. Bound pending presentation queues.

Sector adapter maps existing PublishedState snapshot values into StateImage; all other publication/header metadata remains opaque JSON. Reconstruct through existing codec/snapshot validation, checking digest/layout/tick/count/hash before any live replica mutation. A minimal second test mode proves generic streaming. Keep existing local codec65,536-byte guard and strict clients unchanged; the network image codec has its own128KiB bound. Add a trusted per-binding publication sink in authority attachment before local encoding; only ordinary local bindings require the existing byte encoder. Pass detached publication data to streamed sinks. Use an explicit sector remote adapter to deliver validated publication objects rather than increasing the global local codec limit. Client acceptPublication returns accepted/ignored/rejected after whole publication-schema and snapshot validation. Remote production stays locked until the initial validated-state ACK has been emitted successfully; no port-storage ACK enables it. Gate remote result/event presentation by the authority-supplied publication sequence while preserving early outbox reconciliation and strict behavior. A trusted notification sink supplies next sequence for active tick/control effects, current sequence for already-covered admission duplicates/rejections; original replay/cache data is unchanged. Mode validation and client acceptance must be an explicit success-returning contract so ACK cannot precede validation.

Host stream wrapping belongs at the utility mode boundary before the port; hidden transport forwards opaque bounded stream packets, never loads sector gameplay. Existing local MessagePort peers stay full-state unless explicitly attached as streamed peers. Guest stream reconstruction happens beside the client; hidden transport stays mode-independent. Extend trusted attachment options to select streaming deliberately, default off, with the effective latest payload cap learned from RTC readiness. Reserve framing overhead; require the negotiated cap to carry4KiB input plus headers, otherwise reject clearly. Do not reuse MessagePort maxDatagram as the RTC cap. Guest endpoint consumes a remote Link with the matching stream wrapper; commands retain original bytes.

## Presentation

Add a bounded timeline sampled100ms behind newest authority time, without changing confirmed SimState. Mode adapter extracts stable-ID keyed positions/headings plus a discontinuity key. Interpolate only approved crew/room-object positions and shortest-arc headings; do not interpolate health, votes, targets or resources. Reset/snap on seat/sector/target generation, pause/end, teleport or epoch change. Freeze at latest known sample on a dead link; never extrapolate or predict. Cap samples/time range and release all on disposal. Existing couch rendering remains unchanged; Net-3d online UI consumes this presentation API. Native gate demonstrates the separate view without claiming a finished online screen.

## Process integration and proof

Extract/reuse the existing hidden transport owner (one window per host) and make it usable without a utility for guests: main owns hidden BrowserWindow, typed attempt control, transferred peer ports, source/frame checks and generation cancellation. Host endpoints connect to existing utility via hostHandle.attachPeer(...streamed:true); guest endpoints connect to visible client ports. Keep host ready handshake compatible with Net-3a. No arbitrary ipcRenderer/module/file API. A standalone guest transport does not allocate a simulation authority. Trusted signalling adapter exchanges bounded descriptions/candidates through main; production WebSocket provider comes Net-3c. Bridge ACKs establish port readiness before RTC data can arrive, so first full state cannot be lost before subscriptions.

Native gate must run two separate Chromium renderer processes and a real utility, actual RTCPeerConnections and the production stream/port boundary. A local in-memory broker issues random per-attempt one-use tickets and relays bounded SDP/ICE; no STUN/TURN credentials needed for loopback. Verify actual direct selected pair without recording addresses; initial full validated/ACKed; delayed command applied; 20Hz cadence; delta reduction; reliable control full; dropped/reordered latest recovery; visible renderer stall independent authority; disconnect neutralization; wrong ticket/identity; setup cancellation and process cleanup. Inject packet loss at the harness boundary and label it; it is not proof of arbitrary WAN behavior. Forced relay/two physical PCs await service and credentials integration, explicitly NOT RUN here.
