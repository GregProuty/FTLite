# Net-3d: playable online sector sessions

Status: approved by the user for subagent execution; builder check complete. Continues source `7598a47`, evidence `49bcf2a`, on `codex/net-3`. Slice details originated as controller implementation choices and were included in the approved design.

## Outcome and boundaries

Connect the existing application to the Net-3c service and Net-3a/3b transport. Two separate local Electron application instances can Host/Join by code, ready up, start, control only their assigned seats, lose a guest, run that seat's sector bot, and reconnect the original human to a validated full state. Couch play remains available. The real application's controls and renderer must participate in the proof; a second test-only composition of networking classes is insufficient.

The parent design remains authoritative: `2026-11-14-net-3-internet-sessions-design.md`, especially sections3–6 and11. Protocol2, SIM_VERSION35, checkpoint2 and replay2/3 remain unchanged unless a concrete serialization change requires a separately justified revision. No gameplay re-bless. Main owns credentials and lifetimes; utility owns authority; hidden Chromium owns RTC; visible renderer owns input/UI/replica. Generic transport/service code never imports sector mechanics.

Net-3e still owns the independent utility lease gate, checkpoint mirroring, explicit rehost and deployed internet proof. Consequently Net-3d's playable entry is development-only and restricted to an explicitly configured loopback service. Packaged builds show online as unavailable until3e enables it. Do not wire the intended deployed endpoint into a live playable path before the utility gate exists. A main-process renewal timer is not a fencing guarantee. No deployment, secrets, live TURN, billing or WAN claims in this slice.

## Current seams and approach

`main/index.ts` currently only opens the visible window; `preload/index.ts` exposes suspend/resume. `app/session.ts` constructs couch authority through `localRuntime.ts`. `serviceClient.ts` is an injected in-memory authenticated service client. `startGuestTransport()` can own a hidden RTC window without an authority; `startHostProcess()` creates its own hidden window and utility. Existing `room-service-smoke.cjs` proves pre-start native readiness followed by committed start, utility creation and attachment.

Use a main-process coordinator with injected platform/service/store/clock seams and a separate Electron adapter. Both host and guest create a standalone transport before start. After service commitment the host starts the existing utility owner and attaches the already-ready standalone RTC ports. Its existing utility transport bridge may remain idle; avoid restructuring proven host-process startup solely to remove that extra window. Own and close both windows. This costs one extra hidden host window until a measured cleanup justifies changing that seam.

Retain a separate online renderer session; share renderer/audio/HUD dependencies through a small application session interface rather than adding networking branches throughout couch simulation. Add a DOM menu overlay for text entry and lobby controls above the existing Pixi game; no new UI framework.

## Player flow and room configuration

Home: **Couch play**, **Host**, **Join**, **Reconnect** (only when a stored seat exists). The saved credential is called a seat, not a saved game. Do not imply that reconnect can restore a dead host. Disabled online entries explain that online development needs local service configuration.

Host chooses crew capacity1–4, default2. Capacity fixes simulation playerCount and ship: Skiff1–2, Cutter3–4, exactly `shipForCrew`. Empty seats at start are sector bots; they cannot be newly claimed after roster freeze. Lobby shows code, occupied players, empty bot seats, readiness, and **Ready**, host-only **Start** / **Remove player**, **Leave**. Host cannot remove self. Start requires all occupied humans ready, current native/service routes ready, and matching roster revision. One-person start remains useful for smoke/debug; no mandatory extra human.

Join accepts eight Crockford characters, trims outer whitespace and uppercases. No freeform service URL is accepted from renderer. Room service currently requires compatibility before returning a snapshot and has no discovery endpoint. To avoid new service surface, main tries the two compiled sector layout compatibilities (Skiff then Cutter), once each, advancing only on `incompatible`. Never retry a different layout on unauthorized/not-found/rate-limit/transport errors. This costs at most two join requests; failure text remains a compatibility error after both disagree. Persisted reconnect uses its stored layout compatibility directly and never falls back to an uncredentialed join. Validate returned capacity/layout and build init from that capacity, not occupied-human count; sparse seats never get renumbered.

The main sector factory builds validated RunInit using DEFAULT_SEED2026, DEFAULT_CHARACTERS, baseline unlocked content (empty unlock list), compiled digest and resolved layout. This keeps online initialization independent of either renderer's profile. No arbitrary renderer-provided init, player ID, URL or bytes. After the service's proposal/commit, validate committed init/hash/run/compatibility before creating the utility. Handle event and reply duplication exactly once by run/generation. If commitment succeeded but delivery was lost, fail closed/reconnect; never construct a second utility from an unconfirmed guess.

Running UI uses the existing player HUD with assigned logical seat. A compact status strip offers pause, leave and reconnect/error status without hiding the game. Game end presents the result and Return to menu; no local restart of the old frozen room. Couch progress/telemetry semantics remain unchanged; online does not write couch progression in this slice.

## Main-owned session and IPC

`src/shared/onlineSession.ts` defines strict runtime-validated, bounded renderer operations: host(capacity), join(code), reconnect(), ready(boolean), start(), removeSeat(seatId), retry(), leave(), forgetSeat(), and status subscription. Only removeSeat takes a logical seat ID, validated against the authenticated host's current lobby. Gameplay ownership is never selectable through IPC. All operations return fixed typed outcomes, never raw exception strings. One active session per app; at most one lifecycle operation in flight, with ready changes coalesced to the last explicit value. A monotonically increasing owner epoch invalidates every awaited completion after leave/replacement/window destruction.

Status is a detached bounded record: phase, role, own seat, code, safe roster, retry countdown, fixed error code and available actions. Phases: idle, creating, joining, lobby, connecting, syncing, running, paused, reconnecting, ended, error. Service phase lost maps to a stopped recoverable error with explanation that rehost arrives in3e; do not label an unmirrored game saved.

Electron IPC handlers require the exact registered visible webContents and its main frame; deny subframes, hidden windows and unregistered renderers. Preload exposes named methods plus unsubscribable status/port/lifecycle listeners, no generic invoke/send. Validate inbound and outbound status. Ports carry a local monotonically increasing attachment epoch, runId, hostGeneration and assigned seat; reject/close stale or duplicate transfers on both sides. Renderer acknowledges attachment readiness before input scheduling. Cancellation closes untransferred ports; stale async factories close resources on resolution. Closing the visible window disposes owner and removes handlers/listeners.

Port delivery uses the existing Electron transfer pattern: preload validates main's message, then transfers the port using `window.postMessage`; a renderer-owned typed facade supplies `onPort`. Ordinary methods and status subscriptions use contextBridge. Do not pass MessagePort objects through contextBridge callback cloning. Source: [Electron MessagePorts](https://www.electronjs.org/docs/latest/tutorial/message-ports), checked2026-11-15, plus the repository's native smoke/transport preloads.

Main configuration reads only a non-secret `FTLITE_LOCAL_SERVICE_URL` in development, validates loopback HTTP URL using the existing service client's policy and denies credentials/path/query/fragment. No root .env loading. One configured origin cannot silently change while a seat/session is active. Native fetch/WebSocket availability must be verified under pinned Electron37.10.3 in the application smoke; inject structural adapters for tests, no new network dependency by default.

## Private persistence

One versioned seat record under `app.getPath('userData')`, with service origin, roomId/code, compatibility, seatId/generation and token. Main-only code performs strict validation and an8KiB read cap. Write a unique sibling temporary file then atomic rename; serialize writes and removals so a late write cannot resurrect a forgotten seat. A single saved seat is sufficient; creating another room replaces it only after successful durable save. Failed/corrupt/oversized/unknown-version reads surface fixed storage status and never expose contents.

Persist a newly issued token before connecting/publishing lobby success. On write failure, retain the credential only in the active main process and show a clear nonpersistent-session warning, allowing play; never claim restart recovery. Reconnect writes refreshed generations only for the current owner epoch. Leave stops play but retains the seat; Forget deletes it and cancels current work before removal. Tokens never cross renderer/hidden-window IPC or enter URLs/logs/errors/crash dumps. Main passes only transient RTC ticket/ICE material to transport. File atomicity is not a claim of encryption at rest; private userData follows the parent requirement.

## Transport, start and failure ownership

Keep at most one current attempt per guest seat and one issuance request per guest; serialize issuance requests when necessary to avoid depending on stronger equal-generation correlation than the service wire supplies. Register link-issued and call startAttempt synchronously before processing subsequent signals; never await native readiness in the event dispatch path. Bound forwarded service operations by existing client limits, close on overflow; no unbounded application signal queue. Every callback verifies owner epoch, host/seat generation and attempt ID.

Keep transport-window exit subscriptions after readiness and expose a bounded native attempt-close subscription; today's standalone helper only returns the controller and is insufficient to observe every post-ready death. The Electron adapter wraps the underlying transport owner, while the coordinator differentiates intentional replacement from unexpected loss by current attempt identity.

Loopback proof uses empty ICE servers and explicitly records no TURN. Retain a provider seam for3e, but no fake fallback credentials. Report link-ready only after native channel/ticket authentication. Keep peer ports private until committed start. Attach host visible renderer through its own receive-time MessagePort and each guest through streamed RTC with negotiated latestPayloadLimit. Host input is asynchronous too. Never route guest bytes through the host visible renderer.

During active local development, renew the service lease every5s with one current random nonce and discard stale replies. On failed/expired renewal, service loss/fence, host renderer death, utility/transport death, suspend or clock discontinuity, dispose active authority and peers and show stopped state. Do not silently restore/resume. This is local-slice lifecycle hygiene, not the independent12s utility gate promised by3e. Guest signalling/RTC loss enters bounded reconnect. The host remains alive only while its own service and utility are healthy; guest loss alone does not stop everyone.

Explicit Leave performs best-effort host-release with a bounded request then tears down all owned resources. No checkpoint durability promise. Parent power/visibility listeners must not auto-resume online sessions. Guest focus/visibility loss reliably neutralizes input and stops production; host focus loss behaves the same and does not globally pause. OS suspend stops the online session as above. Couch retains its existing behavior.

## Sector producer handoff and renderer input

The current sector mode retains bot memory but does not run disconnect bots. Add a sector-owned producer manager around existing `createBotClient`, loopback client and authority hooks. Generic ModeHost/hostRuntime continue passing seat ownership and link lifecycle without selecting bot behavior. Every vacant or disconnected sector seat has one strict local bot; attached human seats have one receive-time producer. Bots decide from last published state outside simulation steps, using existing beforeControls/beforeTick boundaries. No direct bot mutation of SimState.

Transitions retire the old producer, neutralize held state and resolve pending work through existing authority detach semantics before binding the replacement. Queue transitions at safe completed boundaries; coalesce by seat/generation and prevent old close callbacks from retiring newer owners. Rejoin retires the bot, attaches the new human, sends full state/high-water and waits for the existing streamed full-state ACK before accepting human production. Fresh UI/outbox begins from validated watermarks; never carry abandoned commands from the old producer. Rejoining never auto-unpauses. Capture actual bot controller memory in checkpoints and preserve it when restoring; do not keep the current inert memory placeholder.

Online renderer consumes the existing streaming client/state timeline, receive-time outbox and card controller. Physical local player0 (primary keyboard or selected first controller) maps exclusively to assigned logical seat. Secondary keyboard/controller inputs never create additional online players. Device replacement neutralizes first; UI text entry consumes no gameplay input. Schedule active input/neutral frames at60Hz independently of Pixi drawing, translate against latest confirmed publication, respect outbox budgets, and stop while unfocused, disconnected or syncing. Reliable focus neutralization is mandatory. Use existing100ms interpolation timeline and player HUD; freeze on loss, no extrapolation. Input/renderer disposal releases all listeners, state and ports.

Concrete stream additions: accept an otherwise ordinary held frame over reliable-ordered only when all held values are neutral; keep its normal per-seat sequence/tick/run validation so delayed older held traffic cannot undo neutralization. Add `neutralize(player)` to the client using a fresh held sequence, never a gameplay command ID. Keep nonneutral held frames on the latest channel. The host stream binding must independently gate input until a valid ACK for an actually transmitted full image; `full-received` alone is not permission, and unknown/unsent ACKs do not unlock. Do not buffer pre-ACK input; discard it without consuming command IDs. Current client-side ACK gating alone does not enforce this on an untrusted peer.

Presentation samples become optional draw-only crew coordinates keyed by logical seat, passed to renderer/crewSprites; never temporarily rewrite Position components. Cache a detached visual snapshot before stream disposal so a disconnected screen can freeze safely after the confirmed replica is released. Dispose this frozen view on replacement/exit. Main uses an epoch-checked renderer `viewState` hint (synced/running/paused/ended) for menu status only; it cannot grant authority, change service readiness or bypass stream ACK gating.

Execution clarification: the current-epoch synced hint may finish the local reconnect attempt and cancel its retry/UI watchdog, keeping the30s budget active through actual renderer synchronization. It never changes host ingress, producer ownership, service/native readiness, utility creation or resume. A false hint only misreports the caller's own progress; the independent host full-state ACK gate remains required.

## Required proof

- Unit tests: strict IPC/sender/port ownership, input at nonzero seat, status redaction, one-operation bounds, stale async completion, corrupt store and late-write/forget race, both ship compatibilities, sparse roster start, duplicate committed event/reply, failed start cleanup.
- Sector tests: loss during a pending command and held movement, bot advances through published-state path, human↔bot↔human without duplicate IDs or dual producers, old close after replacement, paused reconnect stays paused, actual bot memory capture/restore, fake second mode still independent.
- Retry tests: delays1,2,4,8 seconds capped8; total30s monotonic attempt window including async waits; explicit retry after timeout; respect service retryAfterMs without extending the window; terminal authentication/compatibility/storage-invalid failures do not loop. Leave/replacement cancels every timer/port/attempt; no roster expansion.
- Actual application proof: launch two separate Electron processes with separate temporary userData directories against actual local workerd. Drive real menu Host/Join/Ready/Start, show assigned-seat player HUD, apply guest-seat input and verify host/guest agreement. Disconnect/restart guest with persisted token; verify bot takeover, increased seatGeneration, full ACK before resumed input, and no automatic unpause. Run a capacity4 sparse-seat case and both ship paths. Include blur neutralization, cancellation during connection, invalid code and incompatible digest. No token/address/SDP/candidate output.
- Track actual owned process exits and clean exact temporary roots on pass/failure/timeout; include injected child failure and launcher timeout. Never global-kill Electron/workerd. Retain machine-readable summaries with source revision and limitations.
- Full root/service tests, typechecks/builds; existing host/RTC/service native gates where affected. Run acceptance and cross-engine replay once for producer lifecycle changes; retain original30s target and report inherited failure distinctly. No re-bless to conceal divergence.

Completion requires application-level evidence, not merely coordinator unit tests. Deployed service, live TURN/forced relay, independent utility lease fencing, checkpoint recovery and two physical computers remain NOT RUN until3e.
