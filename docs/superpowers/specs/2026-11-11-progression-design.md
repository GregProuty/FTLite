# Progression and Permadeath (Run-iii) Design

Status: approved 2026-11-11 under the autonomous feature loop (`docs/roadmap.md` item 10, the last of the ten); every open choice took the recommended option. Parent: `2026-11-09-foundation-design.md` §1 (sub-project 4), §4 (authoritative state, named RNG streams), §7 (session flow), §14 ("the ship as a character"). Builds on Run-i and Run-ii: the run block, scrap, the record and the acceptance table.

## 1. Goal

A run ends with a **score**; the score and a few milestones feed **unlocks** that persist on disk across runs as small starting bonuses; every run's ship has one **quirk**, a named flaw or virtue drawn from the seed that changes one rule for the whole run; and the game-over and lobby screens show the player's progress. **Permadeath** is stated as a rule: nothing of a run survives its end except the record and the unlocks it earns; there is no mid-run save or continue.

**Out of scope:** choosing which unlock to equip (every earned unlock applies); new characters; a run history screen beyond the lobby line; quirk selection or re-rolls; cloud or cross-machine progress; achievements beyond the three unlock milestones.

## 2. Options considered

- **Where progress lives:** (a) `localStorage` beside the telemetry history, through a tiny store in `app/` with a pure reducer in `sim/` **(recommended, chosen)**: same pattern as 4-ii, testable without a browser; (b) a file through the Electron main process: needs IPC and a schema; (c) in the telemetry history itself: fragile to the 50-record cap.
- **What unlocks are:** (a) three starting bonuses that all apply once earned **(chosen)**: no selection UI, visible on the first tick; (b) new characters: needs authored traits; (c) tuning multipliers: invisible.
- **Quirk source:** (a) a new seventh stream `quirk` appended to `STREAM_NAMES`, one draw at `createSimState` **(chosen)**: every existing stream keeps its seed; (b) the `cosmetic` stream: reserved for rendering; (c) chosen by the player: not "the ship as a character".
- **Score formula:** (a) nodes, victory, scrap and kills with fixed weights **(chosen)**: rewards progress and fighting, readable; (b) survival time only: today's score, flat; (c) a per-crew contribution: Run-iii is not the place for a leaderboard.

## 3. Score (`sim/score.ts`, pure)

`runScore(r: Omit<TelemetryRecord, 'score'>): number = SCORE_NODE × r.run.nodesReached + (r.endReason === 'victory' ? SCORE_VICTORY : 0) + r.run.scrap.earned + SCORE_ENEMY × r.enemy.destroyed + SCORE_BOARDER × r.boarders.killed`; it reads only those existing fields. `TelemetryRecord` gains `score: number`: `telemetryRecord` assembles the record without `score` as today, then returns `{ ...record, score: runScore(record) }` (still pure). Examples: a victory at `nodesReached 7` with `scrap.earned 145`, `enemy.destroyed 0`, `boarders.killed 0` scores `700 + 500 + 145 = 1345`; a hull loss (`endReason 'hull'`) at `nodesReached 3` with `scrap.earned 45`, `enemy.destroyed 0`, `boarders.killed 2` scores `300 + 0 + 45 + 0 + 10 = 355`; a fresh record scores 0. Weights: `SCORE_NODE 100`, `SCORE_VICTORY 500`, `SCORE_ENEMY 20`, `SCORE_BOARDER 5`.

## 4. Progress on disk (`sim/progress.ts` pure, `app/progressStore.ts` storage)

```ts
interface Progress { version: 1; runs: number; victories: number; bestScore: number; bestNodes: number; unlocked: string[] }
```

`EMPTY_PROGRESS = { version: 1, runs: 0, victories: 0, bestScore: 0, bestNodes: 0, unlocked: [] }`. `applyRun(p, record): Progress` (pure, returns a new object): `runs + 1`; `victories + 1` on `'victory'`; `bestScore = max`, `bestNodes = max(nodesReached)`; then every unlock whose condition holds on the **new** progress and record is appended to `unlocked` in `UNLOCKS` order if absent. Unlocks (`UNLOCKS`, ids are stable strings):

| id | name | condition (after the run is counted) | start bonus |
|---|---|---|---|
| `scrap-reserve` | Scrap reserve | `runs >= 1` | the run starts with `UNLOCK_SCRAP = 30` scrap (`scrapEarned` counts it) |
| `torpedo-rack` | Torpedo rack | `bestNodes >= 4` | `torpedoStock = min(TORP_CAP, TORP_START + UNLOCK_TORPEDOES (2))` |
| `veteran-crew` | Veteran crew | `victories >= 1` | every crew member starts one Repair level higher: with `level` the character's head-start Repair level (0 for most, 3 for Okoro) and `next = min(level + 1, SKILL_MAX)`, `xp[xpIndex(pid, Repair)] = XP_THRESHOLDS[next]`, assigned directly after `applyHeadStarts` like a head start (not multiplied by Slow Learner; `addXp` is not used) |

`progressStore.ts`: `PROGRESS_KEY = 'ftlite-progress'`; `loadProgress(storage): Progress`; `saveProgress(storage, p)` (failures swallowed), both over the existing `RecordStorage` interface. `loadProgress` sanitizes field by field: a missing key, unparsable JSON, a non-object root or `version !== 1` → `EMPTY_PROGRESS`; otherwise each of `runs, victories, bestScore, bestNodes` is kept when it is a finite number `>= 0` and is 0 otherwise; `unlocked` is the input array filtered to strings that are known `UNLOCKS` ids, de-duplicated, in `UNLOCKS` order (a non-array → `[]`). A throwing `getItem` → `EMPTY_PROGRESS`; a throwing `setItem` is swallowed. `main.ts` wires `loadProgress: () => loadProgress(localStorage)` and `saveProgress: (p) => saveProgress(localStorage, p)` into the session (both optional deps; the tests' harness passes an in-memory storage).

## 5. Start bonuses and the quirk in the sim

`createSimState(layout, playerCount, seed, characters: readonly number[] = DEFAULT_CHARACTERS, options: SimOptions = {})` with `export interface SimOptions { unlocked?: readonly string[]; quirk?: number }`. Existing calls are unchanged; a caller that needs options passes `characters` explicitly (the session passes `DEFAULT_CHARACTERS`; the test helper `makeState(players, seed, characters = RECRUITS, options = {})` forwards both).

Creation order inside `createSimState` (exact): `deriveStreams(seed)` (the master is drawn in `STREAM_NAMES` order, `quirk` last, so every earlier stream keeps its seed); the map from `rng.map` as today; then `run.quirk = nextInt(rng.quirk, QUIRK_COUNT)` (exactly one draw, always, before any override); then `if (options.quirk !== undefined) run.quirk = options.quirk`; then `applyHeadStarts`; then the start bonuses in `UNLOCKS` order. Nothing else draws from `rng.quirk`, ever.

- `run.startBonus: number` is a bitmask over `UNLOCKS` order (bit `i` set when `UNLOCKS[i].id` is in `options.unlocked`); unknown ids are ignored. The bonuses change initial state only; nothing reads `startBonus` afterwards except the record. The golden replay and every existing test pass no options, so their initial state is unchanged apart from `quirk`.
- `rng.quirk` is the **seventh** stream (`STREAM_NAMES = ['hazards', 'director', 'combat', 'loot', 'cosmetic', 'map', 'quirk']`). The override exists for gates and fixtures; the golden uses the natural draw. `QUIRK_COUNT = 6`.

Quirks (`sim/quirks.ts`): `QUIRKS: readonly { id: string; name: string; text: string }[]`, `QUIRK_NAMES = QUIRKS.map((q) => q.name)`, and one pure hook per rule, each returning the quirk's value when `state.run.quirk === idx` and the neutral value (`1` for a multiplier, `0` for an offset) otherwise. Each hook is read at exactly one expression:

| idx | name | rule | hook and its single site (exact expression) |
|---|---|---|---|
| 0 | Leaky Seals | a closed (not sealed, not open) door passes twice the oxygen | `quirkPassageMult(state)`: `passageFor` in `hazards/oxygen.ts` returns `PASSAGE_CLOSED * quirkPassageMult(state)` on its closed branch (`QUIRK_PASSAGE_MULT 2`); `passageFor` is evaluated per hazard step, nothing caches it |
| 1 | Hot Reactor | heat rises one more unit per hazard tick while overdriven | `quirkHeatRise(state)`: `heatStep` uses `HEAT_RISE + quirkHeatRise(state)` in place of `HEAT_RISE` (`QUIRK_HEAT_RISE 1`) |
| 2 | Sticky Doors | a door stays open twice as long after its zone clears | `quirkDoorDelayMult(state)`: `doors.ts` sets `closeTimer[e] = DOOR_CLOSE_DELAY * quirkDoorDelayMult(state)` where it opens a door (`QUIRK_DOOR_DELAY_MULT 2`) |
| 3 | Lucky Hull | a debris impact costs two hull less; shots are unchanged | `quirkDebrisHullOffset(state)`: in the impact expression of `debris.ts` the debris branch becomes `DEBRIS_HULL_DAMAGE + quirkDebrisHullOffset(state)` (`QUIRK_DEBRIS_OFFSET −2`, so 6); the `ENEMY_SHOT_HULL_DAMAGE` branch is untouched |
| 4 | Twitchy Sensors | the Science warning lead is 4 s longer, manned or not | `quirkLeadOffset(state)`: `scienceLead` returns `(unmanned ? SCIENCE_LEAD_UNMANNED : SCIENCE_LEAD_BASE + SCIENCE_LEAD_SCALE * output) + quirkLeadOffset(state)` (`QUIRK_LEAD_OFFSET 4`: 8 s unmanned, 22 s seated at level 1 skill 0) |
| 5 | Old Drive | the drive takes 75 s to charge | `quirkChargeMult(state)`: `jumpStep` adds `DT / (JUMP_CHARGE_TIME * quirkChargeMult(state))` (`QUIRK_CHARGE_MULT 1.25`; ready tick 4500) |

No quirk makes a draw. The quirk is part of the snapshot (`run.quirk`) and the hash; `startBonus` likewise. Flatten: `run` gains `quirk, startBonus` after `upgrades` (`RUN_FIELDS += 2`); the serialized rng section gains one entry and the header's `rngStates` map gains the key `quirk`, both automatically through `STREAM_NAMES` (`HEADER_FIELDS` unchanged). `SIM_VERSION = 15`; version-14 snapshots are rejected.

## 6. Session flow and permadeath

- `SessionDeps` gains two optional members: `loadProgress?: () => Progress` and `saveProgress?: (p: Progress) => void`. `main.ts` wires `loadProgress: () => loadProgress(localStorage)` and `saveProgress: (p) => saveProgress(localStorage, p)` (each inside the same try/catch pattern as `saveTelemetry`). The tests' harness passes an in-memory `RecordStorage` through the real `loadProgress`/`saveProgress`.
- In `createSession`, before the first frame: `let progress = deps.loadProgress?.() ?? EMPTY_PROGRESS; let newUnlocks: string[] = [];` and `lobbyMessage()` = `` `${LOBBY_MSG}   Runs ${progress.runs}  Best ${progress.bestScore}${progress.unlocked.length ? `  Unlocked: ${unlockNames(progress.unlocked).join(', ')}` : ''}` `` (`unlockNames` maps ids to `UNLOCKS` names). The initial `message`, and the two game-over returns to the lobby (`New seed. …`, `Same seed. …`), use `lobbyMessage()` in place of `LOBBY_MSG`.
- `start()` calls `createSimState(deps.layout, playerCount, seed, DEFAULT_CHARACTERS, { unlocked: progress.unlocked })` and clears `newUnlocks`.
- On the ending tick, in this order: `const record = telemetryRecord(state, seed)`; `deps.saveTelemetry?.(record)`; `const next = applyRun(progress, record)`; `newUnlocks = next.unlocked.filter((id) => !progress.unlocked.includes(id))`; `progress = next`; `deps.saveProgress?.(progress)`; then `phase = 'gameover'` and the banner as today (unchanged text).
- The frame's `buildHudModel(...)` call gains a sixth argument `phase === 'gameover' ? { bestScore: progress.bestScore, runs: progress.runs, victories: progress.victories, newUnlocks: unlockNames(newUnlocks) } : null`; `buildHudModel(state, slots, phase, message, credits = null, progress: HudProgress | null = null)` with `export interface HudProgress { bestScore: number; runs: number; victories: number; newUnlocks: string[] }`. Every existing call site is unchanged (default null).
- Game-over summary (`HudModel.summary`), in this exact order: (1) `` `Survived ${clock}  ${END}  Reached node ${n} of 8  Score ${score}` `` (today's headline plus the score, where `score` is `runScore` of the state's record); (2) the first-down/first-death line; (3) the never-manned line; (4) the longest-idle line; (5) `` `Ship: ${QUIRK_NAMES[state.run.quirk]}` ``; (6) when `progress` is non-null, `` `Best ${bestScore}   Runs ${runs}   Victories ${victories}` ``; (7) when `progress` is non-null and `newUnlocks` is non-empty, `` `Unlocked: ${newUnlocks.join(', ')}` ``; then the per-crew gains lines (up to four). The maximum is `7 + 4 = 11` lines; `hud.ts` allocates **eleven** summary rows (today eight).
- The clock line gains the quirk name: `` `HULL ${hull}   TIME ${s}s   node ${c}/${columns}   ${quirk}` `` with `HudModel.run.quirk: string` (`QUIRK_NAMES[state.run.quirk]`, `''` without a state, in which case the trailing `   ` is omitted: the no-state clock reads as today).
- Permadeath, stated: a run's state is discarded at `start()`; the only data crossing a run end are the telemetry record and `Progress`. Crash snapshots are diagnostics, not saves.
- Record: `run` gains `quirk: string` (`QUIRK_NAMES[run.quirk]`) and `unlocks: string[]` (`UNLOCKS.filter((_, i) => run.startBonus & (1 << i)).map((u) => u.id)`); `score` as §3. Acceptance table: column `score` appended after `scrap` (`String(r.score)`).

## 7. Tuning (first pass)

`SCORE_*` as §3; `UNLOCK_SCRAP 30`, `UNLOCK_TORPEDOES 2`; `QUIRK_COUNT 6`; the quirk factors as §5 (`QUIRK_PASSAGE_MULT 2`, `QUIRK_HEAT_RISE 1`, `QUIRK_DOOR_DELAY_MULT 2`, `QUIRK_DEBRIS_OFFSET −2`, `QUIRK_LEAD_OFFSET 4`, `QUIRK_CHARGE_MULT 1.25`).

## 8. Tests (vitest, node)

Helpers (`tests/helpers/sim.ts`): `makeState(players, seed, characters = RECRUITS, options: SimOptions = {})`; `quirkState(k, seed = 1)` = `makeState(2, seed, RECRUITS, { quirk: k })`; `CONTROL_QUIRK` = the index of a quirk the test under hand does not exercise (each behavioural test names its control explicitly). `rec(over)` in `tests/acceptance.test.ts` is the existing record builder.

- Score: `runScore` on the three §3 records built with `rec`: 1345 (`endReason 'victory'`, `run.nodesReached 7`, `run.scrap.earned 145`, `enemy.destroyed 0`, `boarders.killed 0`), 355 (`'hull'`, 3, 45, 0, 2), 0 (`rec()` defaults); `telemetryRecord(s, 1).score === runScore(telemetryRecord(s, 1))` on a state with `nodesReached 2`, `scrapEarned 30`, `boardersKilled 1` (`200 + 30 + 5 = 235`).
- Progress: `applyRun(EMPTY_PROGRESS, rec({ endReason: 'hull', run: {…nodesReached 2…} }))` → `{ runs 1, victories 0, bestScore 200 + earned, bestNodes 2, unlocked ['scrap-reserve'] }`; applying a second record with `nodesReached 5` → `runs 2`, `bestNodes 5`, `unlocked ['scrap-reserve', 'torpedo-rack']`; a third with `'victory'` and `nodesReached 7` → `victories 1`, `unlocked` gains `'veteran-crew'` last; applying a victory first (from empty) still yields `['scrap-reserve', 'torpedo-rack', 'veteran-crew']` in that order; a lower-scoring later run keeps `bestScore`/`bestNodes`; the input object is deep-equal to its copy afterwards. Store (in-memory `RecordStorage`): save/load round trip equals the input; missing key → `EMPTY_PROGRESS`; `'{'` → `EMPTY_PROGRESS`; `'[]'` → `EMPTY_PROGRESS`; `{ version: 2, runs: 3 }` → `EMPTY_PROGRESS`; `{ version: 1, runs: '3', victories: -1, bestScore: 12.5, bestNodes: NaN, unlocked: ['torpedo-rack', 'bogus', 'scrap-reserve', 'torpedo-rack'] }` → `{ runs 0, victories 0, bestScore 12.5, bestNodes 0, unlocked ['scrap-reserve', 'torpedo-rack'] }`; `unlocked: 'x'` → `[]`; a `getItem` that throws → `EMPTY_PROGRESS`; a `setItem` that throws → no exception.
- Start bonuses: `makeState(2, 1, DEFAULT_CHARACTERS, { unlocked: ['scrap-reserve', 'torpedo-rack', 'veteran-crew'] })` gives `run.scrap 30`, `telemetry.scrapEarned 30`, `weapons.torpedoStock TORP_START + 2`, Okoro's Repair level 4 and Lindqvist's 1, `run.startBonus 0b111`; `{ unlocked: ['bogus'] }` → `startBonus 0` and a state hash equal to the no-options state's; `torpedo-rack` alone with `TORP_START` already `TORP_CAP` (set the constant's effect by comparing `min`) → `torpedoStock TORP_CAP`; `veteran-crew` on a character whose head start would be `SKILL_MAX` (a fixture character is not available, so the test calls the exported `veteranRepairXp(level)` helper with `SKILL_MAX` and expects `XP_THRESHOLDS[SKILL_MAX]`).
- Quirk: `makeState(2, 7).rng.quirk.s` equals `deriveStreams(7).quirk` advanced by one `nextInt(…, QUIRK_COUNT)` and `run.quirk` equals that draw; the Run-i pins (`hazards`, `director`, `combat` for seed 1) and `deriveStreams(1).map.s` are unchanged; `makeState(2, 7, RECRUITS, { quirk: 5 }).run.quirk === 5` with the same `rng.quirk.s` as without the override; each hook returns its value for its quirk and the neutral value for the other five (a loop over `0..5`). Behavioural, each with `quirkState(k)` and `quirkState(CONTROL)`: (0, control 5) rooms A and I share door edge 0: set `rooms.o2[A] = volume[A]`, `rooms.o2[I] = 0`, `doors.state[0] = Closed`, run `oxygenStep(state)` once: the oxygen moved into I is `2×` the control's (both `> 0`); (1, control 0) `overdrive(state, Weapons)` then one `heatStep`: heat `HEAT_RISE + 1` vs `HEAT_RISE`; (2, control 0) teleport pid 0 onto door tile 0's zone, run until `doors.state[0] === Open`, teleport away, count ticks until `Closed`: `2 × DOOR_CLOSE_DELAY × TICK_HZ` vs `DOOR_CLOSE_DELAY × TICK_HZ` (±1 tick, both asserted exactly from the same start); (3, control 5) `placeDebris(state, A, 1)`, run 1 tick: hull `HULL_MAX − 6` vs `HULL_MAX − 8`; a `placeShot` impact costs `ENEMY_SHOT_HULL_DAMAGE` under both; (4, control 0) `scienceLead` unmanned `8` vs `4`, and seated at level 1 skill 0 `22` vs `18`; (5, control 0) after one `step` `jumpCharge` is `DT / 75` vs `DT / 60` and `seatNavigator` + Confirm every tick first jumps on tick 4500 vs 3600.
- Snapshot: `run.quirk` and `run.startBonus` round trip and each alone changes the hash; `saveSnapshot(s).header.rngStates.quirk` equals `s.rng.quirk.s`; version-14 rejected.
- Session (harness extended with an in-memory `RecordStorage` passed through the real `loadProgress`/`saveProgress`): the lobby message ends `Runs 0  Best 0` with empty progress; a run ended by `downCrew` on the only player saves one record and one progress with `runs 1`, `unlocked ['scrap-reserve']`, and the summary carries `Score N`, `Ship: <quirk name>`, `Best N   Runs 1   Victories 0` and `Unlocked: Scrap reserve` in the §6 order; Cancel then Confirm (new seed, start) creates a state with `run.scrap 30` and `startBonus 1`; a harness whose storage already holds `{ version 1, runs 4, victories 1, bestScore 900, bestNodes 6, unlocked: [all three] }` shows `Runs 4  Best 900  Unlocked: Scrap reserve, Torpedo rack, Veteran crew` in the lobby and starts with all three bonuses. HUD: `clockLine` exact with a quirk name and without a state; the headline strings exact; `buildHudModel(s, slots, 'gameover', '')` without progress gives six lines before the gains (no `Best` or `Unlocked` line).
- Gates: the survival and boarding gates run with each seed's **natural quirk**. Figures are **expected to drift** from the Run-ii baseline; the gate section records, per seed, the quirk name, the new figures and the delta. Pass means what the gate files already assert (survival: neither bot run ends within five minutes and the existing bounds hold; boarding: the existing assertions). The Run-i lever list is re-authorised, in order, only for a seed that fails those assertions. `gate-jump` and `gate-run` pass `{ quirk: 3 }` (Lucky Hull: no debris flies in those gates, so the rule is inert) and keep their end tick 25200 and totals; each test states this in a comment. Golden re-blessed once (version 15; the quirk stream and the two fields are hashed; the golden's natural quirk is recorded in `docs/gates.md`).
- Acceptance: `rec()` gains `score: 0`; the header regex ends `scrap\s+score$`; the row tails gain `\s+\d+$` (`0/0   0` style); the victory row's `score` is asserted as `runScore` of its fields. `npm run acceptance 5 1` rows gain `score`; the Run-ii rows in `docs/gates.md` stay as recorded, the new section gets its own rows.

## 10. Known limitations

Every earned unlock applies with no choice; three unlocks and six quirks are a first authoring pass; progress is per machine and per browser profile (localStorage); clearing site data resets it.
